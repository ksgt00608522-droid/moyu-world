## 已定：技能

### 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `skl_` 前缀 + 名字，如 `skl_ironbone` |
| `name` | 是 | 显示名 |
| `kind` | 是 | `'passive'` 或 `'active'` |
| `desc` | 是 | 一句话描述 |
| `mods` | 被动必填 | 修正项数组，见下 |
| `applies` | 主动必填 | 使用后挂上的状态 id |

### 被动技能

**拥有就生效**，不需要使用。它的修正计入"角色固有"那一段，**吃生命惩罚**。

### 主动技能

**用一次，挂一个状态。** 技能本身不带修正 —— 修正在它挂的那个状态里。

这么设计是为了只留一条施加路径：所有临时修正都来自状态，
公式里也就不用再分"技能修正"和"状态修正"两种。

> 副作用：属性明细里**没有「主动值」这一项** —— 主动技能的贡献算进「状态」，
> 因为它的修正确实在状态里。见 `04-数值与成长.md` 的「面板怎么显示属性」。

**对外叫「法术」。** 素材字段仍然是 `kind: "active"`、指令仍然是 `cast`，
只有给玩家看的字是"法术"：

| 场合 | 用的词 |
|---|---|
| 操作区那个按钮 | **释放法术**（在「行动」组里） |
| 点开的列表 | 法术列表 |
| 被动技能 | 还是叫「技能」 |
| 两者一起看 | **技艺**（操作区「其他」组的按钮） |

> **左栏没有「技能」块。** 左栏只有 **玩家状态 / 状态 / 玩家背包** 三块。
> 技能块原来在左栏（列拥有哪些技能、标被动 / 主动），后来删了 ——
> 它跟技艺弹框内容重复，而弹框更宽、还能写描述；留在左栏只是白占一行高度。
> **被动技能没有因此看不见**：技艺弹框列的就是主动 + 被动。

#### 怎么释放

**「释放法术」按钮在操作区的「行动」组里，不在单独的「技能」组。**
点了弹出一个**模态弹框**，列出拥有的全部主动技能 —— 每条带名字、
「主动」小标签、一句话描述、**释放后挂上哪个状态（以及那个状态改了什么）**、
一个「释放」按钮。点「释放」直接放，弹框关掉。

> 为什么要写"释放后挂上什么"：玩家点开列表就是为了决定放哪个，
> 光看名字和描述决定不了。而状态的修正是通过状态生效的（见上面「主动技能」那段），
> 所以那一句正好把"这个法术到底干什么"说完了。

打字也行，两条路都留着：

```
cast            打开法术列表（跟点按钮一样）
cast 凝神        直接释放（跳过列表）
cast skl_focus  用 id 也行
```

> 操作区**不再有「技能」分组**。原来那组是按"拥有几个主动技能"现生成按钮的，
> 现在改成行动组里一个固定按钮 —— 技能再多也不会把操作区撑长。

### 修正项（mods）

```js
mods: [
  { attr: 'str', add: 1 },     // 加值：力量 +1
  { attr: 'int', pct: 20 }     // 百分比：智力 +20%
]
```

- `attr` 必须是 `js/rules.js` 属性表里的 key（`str` / `int` / `spr` / `dex` / `luk` / `per`）。
- `add` 和 `pct` 二选一。
- 多个修正项**加值先相加、百分比先相加**，不是逐个相乘（见 `04-数值与成长.md`）。

## 已定：状态

状态跟技能是同一类东西 —— 都是"改数值的修正源"，区别在生命周期：
技能是角色**拥有**的，状态是**挂着**的、会自己过期。

### 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `st_` 前缀 + 名字，如 `st_poison` |
| `name` | 是 | 显示名 |
| `kind` | 是 | `'buff'`（正面）或 `'debuff'`（负面） |
| `desc` | 是 | 一句话描述 |
| `unit` | 是 | 计时方式，见下 |
| `turns` | 是 | 持续多久（`manual` / `threshold` 时填 0） |
| `mods` | 否 | 修正项，同技能 |
| `tick` | 否 | 每次计时的附加效果，如中毒掉血 |

### 计时方式（unit）

| 值 | 含义 | 现在能不能用 |
|---|---|---|
| `'step'` | 玩家每走一格减 1，归零消失 | ✅ 已实现 |
| `'time'` | 按真实秒数走，不管玩家在干嘛 | ⚠️ **计时器还没实现** |
| `'manual'` | 不自动过期，得吃解药或到某个事件才解除 | ✅ 判定已就位 |
| `'threshold'` | **不由计时驱动**，去留由外部条件决定 | ✅ 已实现 |

> **"走一格"指真的走过一格，进门不算。**
> 进门是一次"传送到另一个房间"，不是走了一格 —— 所以按 `step` 计时的状态**不递减**，
> `walk` 类任务也**不推进**。这条是隐式的（`js/world.js` 的 `enterDoor()` 从不调
> `move()` 的那些副作用），但很重要：**补上就等于开了个漏洞** ——
> 站在门上反复进出，能刷掉中毒、也能把走路任务刷满。
> 冒烟里有一组断言专门盯着它（"进门不算走一格"），别删。

`threshold` 不是一种"时长"，而是"去留交给别的东西判"。
灵性枯竭 / 耗尽就属于这一类：灵性回到 20% 以上，枯竭自动摘掉。

> **`time` 现在写了会静静地赖着不走。** `js/statuses.js` 的 `tickStep()` 只认 `step`，
> 按真实秒数计时的计时器还没做，所以 `time` 的状态挂上就永远不会过期。
> `tools/validate.mjs` 会直接拦下这种素材，免得埋一个从界面上完全看不出原因的坑。
> 要做这个值得先想清楚两件事：**关掉游戏的那段时间算不算**、以及要不要为它开一个定时器。

### tick

```js
tick: { key: 'hp', delta: -2 }     // 每次计时，生命 -2
```

`key` 目前只允许 `hp` / `ess`（生命与灵性）。
**状态是唯一能自动改这两个值的东西** —— 战斗和物品都还没有。

### 四个正交维度

跟事件点一样，状态是"写了哪个字段就有什么行为"，不看类型名：

| 维度 | 由什么决定 |
|---|---|
| 正负面 | `kind`（只影响配色，不影响逻辑） |
| 改不改属性 | 有没有 `mods` |
| 会不会持续掉血 | 有没有 `tick` |
| 会不会自己过期 | `unit` |

### 查看一个状态的效果

左栏「状态」块里**每个状态名都是一个按钮**，点开弹出一个模态弹框，
里面显示四块内容：

**多个状态并排成标签**（每个只占自己文字那么宽），一行放不下就换到下一行。
一个状态占满一整行太浪费 —— 左栏本来就窄，状态名通常两三个字。

| 内容 | 来源 | 例 |
|---|---|---|
| 描述 | `desc` | 心神专注，脑子转得比平时快。 |
| 剩余量 | 存档里的 `left` | 还能走 3 格 |
| 影响 | `mods` / `tick` | 智力 +2 / 每走一格：生命 -2 |
| 计时 | `unit` | 每走一格减 1 |

- 标题用**状态自己的名字**，右边带一个「正面 / 负面」小标签 ——
  标题写"状态详情"的话，开着好几个就分不清看的是哪个了。
- **描述没写就不画那一块**，不是画一个空的（跟点位状态里的事件点一个做法）。
- 「影响」没东西时明说一句「不改变任何属性。」——
  比整块消失清楚：玩家要能区分"这状态不改属性"和"这块界面坏了"。
- 「剩余量」那句话**跟着计时方式变**：`step` 是"还能走 N 格"、
  `time` 是"还能持续 N 秒"、`manual` 是"不会自己消失"、
  `threshold` 是"不由计时决定"。`manual` / `threshold` 的 `turns` 是 0，
  照 `step` 的写法说成"还能走 0 格"就错了。

打字也能看：`buff 凝神` / `buff st_focus`。

> **剩余量以前是玩家看不到的**（面板只列状态名），
> 所以挂上「凝神」之后完全不知道还能走几步 —— 只能等它自己消失时报一声。
> 现在放进弹框里了。

## 已定：物品

> 物品系统现在**只做「背包」这一层**。装备槽、掉落表、商店都还没有（见文末「待定」）。

### 五分类

物品按用途分成五类，分类表在 `data/items.js` 的 `G.data.itemKinds`：

| 分类 id | 名 | 放什么 |
|---|---|---|
| `consumable` | 消耗品 | 用一次就少一个 |
| `equip` | 装备 | 将来要穿在身上的（装备系统还没做） |
| `material` | 材料 | 攒着，将来拿去合成或交付 |
| `special` | 特殊 | 有专门用途、不属于上面任何一类的东西（钱袋、笔记本） |
| `quest` | 任务 | **剧情道具**：任务会收走 |

分类表字段是 `id` / `name` / `color`。**加分类只改这张表**，不用碰 CSS 也不用碰 JS ——
跟 `npcTypes` / `eventTypes` 是同一个做法。

**分类只决定配色和排序，不决定行为。** 跟事件点、状态一样，物品"能做什么"
看它**写了哪些字段**，不看 `kind` 是什么：

| 写了什么 | 会怎样 |
|---|---|
| `use` | 详情框里出现「使用」按钮 |
| `panel` | 详情框里出现一个打开对应面板的按钮 |
| 两个都没写 | 详情框里只有描述，没有按钮 |

所以"药水能喝"是因为它写了 `use`，不是因为它 `kind: 'consumable'`。

**「任务」类（`quest`）是剧情道具**：不能丢（不过现在**所有**物品都不能丢，
见文末「已废弃」），而且**任务会收走** —— `collect` 类任务交付时按目标数量扣掉
（见 `09-NPC与任务.md`）。

### 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✔ | `itm_` 前缀 + 小写字母数字下划线 |
| `name` | ✔ | 显示名 |
| `kind` | ✔ | 分类 id，必须在分类表里 |
| `desc` | ✔ | 一句话描述 |
| `stack` | ✔ | `true` 可堆叠 / `false` 唯一 |
| `use` | | 使用效果，一串效果（跟事件点的 `onUse` 同形）。写了才能用 |
| `panel` | | 能打开哪个面板：`'wallet'`（钱袋）/ `'notebook'`（笔记本） |

- **`use` 和 `panel` 不能同时写。** 两个都会往详情框里塞一个按钮，
  一个物品只该有一个动作。`validate.mjs` 直接拦。
- **没有 `glyph`。** 物品不出现在地图上，背包里画的是名字。

### 堆叠：两类

| `stack` | 含义 | 存档里的 `count` |
|---|---|---|
| `true` | **可堆叠** | 给几次累加几次，没有上限 |
| `false` | **唯一** | 恒为 1。已经有了再给，等于没给（不报错、不重复） |

**"唯一"不是说"不能拿第二个"，是说"这个东西全游戏只有一个"。**
钱袋、笔记本、剧情道具都属于这一类 —— 再捡一个也没意义。

> 为什么不做"可堆叠但有上限（99 一组）"：那要引入"占几格"这个概念，
> 而**背包不限格数**，多出来的格子没有任何作用。

### 容量：不限格数

背包**不设格子上限**。东西再多也只是标签云多换几行。

> 这是刻意的。限格数就得做"满了怎么办"（丢弃、爆仓、仓库），
> 而那三样都要玩法支撑。玩法还没定，先不加。

### 货币

**货币是数字，不是物品。** 它存在存档的 `wallet` 字段里（币种 id → 数量），
**不占背包格**。钱袋是背包里一个**查看余额的入口**，不是装钱的东西 ——
钱没有"在钱袋里"和"在兜里"两种状态。

**币种表**在 `data/items.js` 的 `G.data.moneyTypes`：

| 字段 | 含义 |
|---|---|
| `id` | 币种标识，如 `coin` |
| `name` | 显示名 |
| `color` | 余额那一行的颜色 |

**现在只有一种：`coin`「金币」。**

> ⚠️ 「金币」是**占位名** —— 命名风格（西幻音译 / 中式古风 / 现代梗）
> 在 `99-待定问题.md` 的 D 组还没拍板。等拍了改 `moneyTypes` 里那一行就行：
> 存档里存的是 id（`coin`），改名不用迁移。

**结构留了多币种。** `wallet` 是一张映射表，余额面板按表逐行画 ——
以后加"银币 / 铜币"只改素材，代码一行都不用动。
**现在不做兑换**（汇率是玩法，等真有第二种币再说）。

**没有钱袋就看不到余额。** 跟"没有笔记本看不到任务清单"是同一个道理：
钱一直在存档里，只是玩家看不见。**这是设计内的，不是 bug。**

> **跟 v5 删掉的那个「金币」不是一回事。** v5 删的是 `player.gold`
> （玩家对象上的一个点数）；现在的是 `wallet.coin`（钱包里的一种币）。
> `player.gold` **仍然是错的目标字段**，`set` 的白名单里没有它，别写回去。

### 两个特殊物品

| id | 名字 | 分类 | 堆叠 | 干什么 |
|---|---|---|---|---|
| `itm_purse` | 钱袋 | `special` | 唯一 | `panel: 'wallet'` —— 点开看各币种余额 |
| `itm_note` | 笔记本 | `special` | 唯一 | `panel: 'notebook'` —— 点开写成一本"书"：两根书签（进行中 / 已完成）切栏、纸面固定高度、内容多了翻页 |

**开局都不带，全靠获得。** 两个都由事件点给（见 `10-事件点.md`）。

**笔记本的「已完成」看的是 `times > 0`（交过几次差），不是 `state === 'done'`。**
可重复任务交付后 `state` 立刻回到 `available`，只有 `times` 记得住它完成过 ——
按 `state === 'done'` 列的话，可重复任务**永远进不了「已完成」这一栏**。

> 所以一个可重复任务可能**两栏都出现**（正在做第 3 轮、同时已经交过 2 次差）。
> 这不是 bug，是它真实的处境。

**笔记本界面一次摊一栏、不并排**：顶上两根书签（进行中 / 已完成）点哪根看哪栏，
单栏内容超过**固定默认高度**就「翻页」（`‹ 第 x / n 页 ›`），不滚动。
这条属于 UI 呈现，细节在 `02-玩法循环与操作.md` 的弹框表。

### 点一个物品能做什么

背包里每个物品是一个**标签**（名字 + 数量，唯一的不写数量），
点开弹出**物品详情弹框**：

| 内容 | 来源 |
|---|---|
| 标题 | 物品名，右边带一个分类小标签 |
| 描述 | `desc` |
| 数量 | 可堆叠的写「持有 N 个」，唯一的写「只有一个」 |
| 按钮 | 有 `use` 就画「使用」；有 `panel` 就画打开那个面板的按钮；都没有就不画 |

**没有「丢弃」按钮** —— 详情框里根本不存在这个东西，
不是"画出来但点了没反应"。

### 「使用」的效果

`use` 是一串效果，跟事件点的 `onUse` 用的是**同一套效果键**
（见 `10-事件点.md` 第三节）。两种形式都存在，素材里写了哪个就走哪个：

| 形式 | 写法 | 现在生效吗 |
|---|---|---|
| **挂状态** | `{ "buff": "st_focus" }` | ✅ 生效 |
| **直接改数值** | `{ "set": { "player.hp": "+20" } }` | ❌ 还是空壳 |

> `set` 仍是空壳（`G.rules.applyEffect` 什么都不做），原因跟事件点那边一样：
> 玩法没定。所以**现在想让一个物品"有效果"，就挂状态**。

**用完数量减一**（唯一的物品则从背包里消失）。这是"使用"的默认行为，
素材不用写 —— 写了 `use` 就意味着"用一次少一个"。

> 以后做装备时，"使用"会变成"穿上"（不消耗），那要另开一个字段。
> 现在不动，装备系统还没做。

### 背包怎么排

**并排成标签，跟左栏「状态」块是同一套做法**：每个物品只占自己文字那么宽，
一行放不下就换行，按内容高度排。左栏窄，一个物品占一整行太浪费。

排序：**先按分类表的顺序**（消耗品 → 装备 → 材料 → 特殊 → 任务），
**同类按素材里出现的顺序**。这样背包不会因为捡到新东西就整块重排。

## 约定（提前定下，避免返工）

- **素材之间引用只走 ID，永不内联对象。** 否则以后批量生成新素材时会破坏已有引用。
- **每个素材必须有 `desc` 字段。** 文字 RPG 的质感全在文案上。
- **ID 规则**：前缀 + 名称 + 序号，如 `mon_slime_01` / `itm_gel` / `skl_bite` / `st_poison`。

这些都由 `tools/validate.mjs` 机械校验（技能 / 状态 / 物品三段），不用靠人记：

- id 前缀与唯一性、`name` / `desc` 齐全、`kind` 取值。
- `mods` 的 `attr` 必须落在属性表里（`str` / `int` / `spr` / `dex` / `luk` / `per`），
  `add` 和 `pct` **二选一**。打错一个字母运行时是**静默失效**，属性就是不变。
- **主动技能不许写 `mods`** —— 修正在它挂的状态里，写这儿会被 `passiveMods()` 忽略。
- 主动技能的 `applies` 必须指向一个真实存在的状态。
- `tick.key` 只允许 `hp` / `ess`，且**只有 `unit` 是 `step` 的状态才配得上 `tick`**
  （其余的根本不计时，写了也永远跑不到）。
- `unit` 是 `manual` / `threshold` 时 `turns` 必须写 0；
  `step` / `time` 时 `turns` 不能是 0（挂上就掉，没有意义）。

物品与货币那几段（`tools/validate.mjs`）：

- 分类表 / 币种表：`id` / `name` / `color` 必填，`id` 不能重复。
- 物品：`id` 带 `itm_` 前缀、`name` / `desc` 齐全、`kind` 在分类表里、
  `stack` 必须是布尔。
- **`use` 和 `panel` 不能同时有**（一个物品只该有一个动作）。
- `use` 若填了必须是非空数组，每一项效果的键只能在白名单里
  （`log` / `cls` / `set` / `give` / `take` / `money` / `buff`）。
- `panel` 若填了只能是 `wallet` / `notebook`。
- **`give` / `take` 的键必须指向真实存在的物品**，值是正整数；
  唯一物品（`stack: false`）不许写大于 1 —— 给了也拿不到第二个。
- **`money` 的键必须指向真实存在的币种**，值是**带符号的字符串**（跟 `set` 一样）。
- 任务的 `reward.items` / `reward.money` 同样要指向真实物品 / 币种（见 `09-NPC与任务.md`）。
