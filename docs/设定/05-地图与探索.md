## 已定

### 地图结构

**三层：世界 → 区域 → 房间。**

| 层 | 是什么 | 放在哪 |
|---|---|---|
| 世界 | 全部内容 | 没有独立文件，就是所有区域加起来 |
| **区域** | 一组房间的归属，有一个「中心房间」 | `data/areas.js` |
| 房间 | 一块矩形格子地图，玩家实际走动的地方 | `data/rooms/<区域>.js` |

**房间制。** 每个房间是一块矩形格子地图，房间之间靠门连接。

#### 区域（`data/areas.js`）

| 字段 | 含义 |
|---|---|
| `id` | 唯一标识，小写字母数字下划线，不带 `room_` 前缀 |
| `name` | 显示名，出现在「地图点位状态」面板里 |
| `center` | 中心房间 id，必须是本区域里的房间 |
| `parent` | 上层区域 id，可选。现在还没有嵌套区域，留着以后做子区域 |

**为什么要这一层：** 房间一多，光看 `doors` 的指向推不出"这屋属于哪一块"，
id 也容易撞车。有了区域，房间可以按 `区域_房间` 命名，素材也能一个区域一个文件。

当前只有一个区域 `hall`（显示名"大厅区域"），包含大厅和四扇门通向的四间屋。

#### 房间（`data/rooms/<区域>.js`）

| 字段 | 含义 |
|---|---|
| `id` | 唯一标识，如 `room_hall` |
| `area` | **必填**，所属区域 id |
| `name` | 房间名 |
| `desc` | 进入时的描述文字 |
| `tiles` | 字符数组，每个字符串是一行。`#` 墙、`.` 地板 |
| `spawn` | 首次进入时的落点 `{ x, y }` |
| `doors` | 门表，键是 `"x,y"`，值是 `{ to, name, back }` |

- `to`：目标房间 id
- `name`：门名，显示给玩家
- `back`：从目标房间返回时的落点 `{ x, y }`，不填则用目标房间的 `spawn`

#### 素材文件怎么摆

**一个区域一个文件。** 房间素材是 `data/rooms/<区域 id>.js`，
文件里用 `G.data.rooms.push( {...}, {...} )` 往房间表里追加。

- 房间多了不用全挤在一个文件里 —— 长对话下改一个房间要读整份素材，很容易改错行
- 新开一个区域就新建一个文件，**并在 `index.html` 里补一行 `<script src>`**
  （`tools/build.mjs` 是照 `index.html` 里的标签内联的，不补就不会被打进产物）
- `tools/validate.mjs` **扫描整个 `data/rooms/` 目录**，不写死文件名，新文件自动纳入校验

**加载顺序有讲究**：`js/data.js`（定义空的 `G.data.areas` 和 `G.data.rooms`）
必须排在 `data/areas.js` 和 `data/rooms/*.js` 前面，否则 push 的目标还不存在。
区域文件之间、房间文件之间的先后不影响结果。

### 坐标约定

`tiles[y][x]`，即 `tiles` 第 y 个字符串的第 x 个字符。**y 向下增大，x 向右增大。**

### 移动规则

- 上下左右各移动一格，走进墙里会被拦下并提示
- **NPC 挡路**，那一格同样走不过去 —— 但提示语跟撞墙分开说
  （「神秘人挡在前面，过不去」而不是「那边是墙」），免得玩家以为地图画错了
- 走到门所在的格子上会提示"这里有一扇 XXX"，输入 `enter` 才进入
- 从 A 进入 B 后，落点由 A 那扇门上标注的 `back` 决定
- **事件点不挡路**，可以走上去。走上去之后：
  - 写了 `onCollide` 的当场自动触发（不用按键）
  - 写了 `onUse` 的等玩家动手（面板上出现互动按钮）
  - 完整规则见 `10-事件点.md`
- 每成功走一步，推进一次"走路"类任务（只推进**已经接取**的，见 `09-NPC与任务.md`）

**一步之内的先后顺序**（`G.world.move()`）：落格 → 对话断开 → 门的提示 →
**事件点触发** → 走路任务推进 → 刷新 → 自动存档。

事件点排在"走路任务"**前面**：踩到机关说一句，比"任务目标达成"更贴近刚发生的事。

### 素材完整性（强制）

下面这些都由 `tools/validate.mjs` 强制检查，**写错直接报错**，不会等到运行到一半才炸。

**区域与归属：**

- 每个房间**必须**填 `area`，漏了报错
- `area` 指向的区域**必须存在**（防 id 拼错）
- 区域的 `center` 必须是**真实存在**的房间，且那个房间的 `area` 必须**指向本区域**
- 区域 id 不能重复，`parent` 若存在必须指向另一个区域
- 一个区域里至少要有一个房间（空区域多半是 `area` 字段写错了）

**房间与门：**

- 房间 id 不能重复（**跨区域文件也算重复**）
- `tiles` 每行等长、上下两行必须全是墙、只允许 `#` 和 `.`
- `spawn` 必须在图内且不在墙里
- 门必须开在墙 `#` 上，坐标在图内
- **每个门的目标房间必须存在，且目标房间里必须有门能回来**
- 每个房间至少有一个门（否则进去出不来）

**NPC 与房间的交叉约束**（NPC 素材本身见 `09-NPC与任务.md`）：

- NPC 的每个出现位置必须指向一个**真实存在**的房间
- 坐标必须在图内、**不能在墙里**、**不能在门格上**（门是通道，站个人会把路堵住）
- **不能开在房间的出生点上**（否则玩家一睁眼就站在别人身上）
- **同一个房间里同一格不能站两个 NPC**（地图一格只画得下一个字）
- **NPC 不能把路堵死。** 校验脚本从出生点出发，按"NPC 挡路"的规则
  （`walkable()` 把 NPC 算成障碍）做一遍 BFS，**每个门格都必须走得到**。
  新增 NPC 时如果正好卡在唯一的通道上，这一步会直接报错

**事件点与房间的交叉约束**（事件点素材本身见 `10-事件点.md`）：

- 事件点的每个出现位置必须指向一个**真实存在**的房间
- 坐标必须在图内、**不能在墙里**、**不能在门格上**、**不能开在房间的出生点上**
- **不能开在 NPC 那一格上** —— NPC 挡路，那一格玩家永远走不上去，
  事件点就成了永远碰不到的东西
- **同一个房间里同一格不能有两个事件点**
- **事件点不参与"路通不通"的检查。** 它不挡路，堵不死任何东西 ——
  上面那条从出生点做的 BFS 只算 NPC，别顺手把事件点也加进去
