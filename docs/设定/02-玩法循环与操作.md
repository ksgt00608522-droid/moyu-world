# 02 玩法循环与操作

> 状态：部分已定（P0 骨架范围）
> 负责：玩家在游戏里做什么、核心循环、指令表、界面布局与输入方式
> 不负责：战斗内部规则（见 03）、数值公式（见 04）

---

## 已定

### 开局流程

1. 首次打开 → 进入角色创建
2. **只能创建一个角色。** 创建后即锁定；存档存在时不再出现创建流程
3. 创建完成 → 直接进入大厅
4. 之后每次打开：有存档就续玩，没有存档才回到创建

### 角色创建

- **是一个独立的整页，不走指令。** 首次打开时游戏主界面整个藏起来，只显示创建页
- 只输入名字，初始属性由 `js/rules.js` 统一给出（不掷骰、不分配点数）
- 名字不能为空，长度上限 12 个字符
- 输入框回车与「进入大厅」按钮等价
- 出错时在按钮上方显示原因，改动输入即清掉提示

### 大厅

- 玩家在大厅内**按格子自由移动**（上下左右各一格）
- 大厅四壁各有一扇门，分别通向别的地方
- 走到门所在的格子上 → 记事提示这里有一扇什么门，**地图点位状态面板里冒出「进入这扇门」按钮**
- 门是**站着才能进**的：没站在门格上时，那个按钮根本不存在，也就点不出"进入"
- 键盘上按空格 / 句号 / 小键盘中键同样可以进门
- **进门不算走一格。** 它是一次"传送到另一个房间"，不是走过一格 ——
  所以按步计时的状态不递减、`walk` 类任务也不推进。
  理由：不然站在门上反复进出就能刷掉中毒、刷满走路任务。详见 `06-物品与技能.md` 的 `unit` 表。

**三栏布局。** 左栏是"玩家自己的东西"，中栏是"地图与叙事"，右栏是"二级操作与通用操作"。

三处容易搞错的地方：

1. **记事横跨"地图 + 地图点位状态"两块的宽度**，不是只在地图下面。
2. **输入行只在中栏底下，不占满全宽**，也不跟操作按钮挤在一起。
3. **左右两栏各自上下分块**：左栏 = 玩家状态 / 状态 / 玩家背包，
   右栏 = **二级操作（上） / 操作区（下）**。顺序别调 —— 二级操作的内容
   会随情况变长（对话选项一多就长），所以是它吃剩余空间、内部滚动；
   操作区是固定的那几组通用指令，按内容高度就好。
4. **左栏吃剩余空间的是「玩家背包」，不是「状态」。**
   状态块按内容高度（挂几个状态就占几行，并排成标签、装不下换行），
   背包同理（物品并排成标签）—— **两块都是"按内容高度、装不下内部滚动"**，
   余量给背包是因为它最可能变长，而且它在最下面，长出来不挤别人。
   > 反过来了两次，记一下：一开始是**背包吃剩余**，后来觉得"状态数量会变、
   > 余量该给会变的那块"，换成**状态吃剩余**；现在**又换回背包吃剩余**。
   > 原因是状态块改成**按内容高度**了 —— 它不再需要"余量"来撑，
   > 而"会变的那块"这个理由靠**并排换行**解决：状态多了自己往下长，
   > 长到放不下时内部滚动（`overflow-y: auto`）。
   > 现在背包也是同一套（并排成标签、按内容高度），余量给它是因为它最靠下。

**没有宽度上限。** `#app` 不再限制 `max-width`，窗口多宽就铺多宽。
左右两栏用 `clamp()` 跟着窗口宽走但有上下限，窗口再宽也不会把中栏挤没。

> **左栏的下限比右栏大**（`clamp(250px, 18vw, 300px)` 对 `clamp(180px, 15vw, 260px)`）。
> 因为左栏里有一块 **3 列并排**的属性明细，三列各要装下 `(5+1+0+0)`
> 这样一行十来个字符。这个数是**量出来的**：1100×700 下左栏 190px 时
> 每格只有 52px，而明细文字要 58px，正好装不下（冒烟里有一条
> 「属性明细装得下」盯着它，换更窄的窗口就会红）。

**操作区按用途分组**，分组顺序由 `GROUPS` 决定：**移动 / 行动 / 存档 / 其他**。

- 分组只影响排版，不改变指令本身。
- **没有「技能」分组**（已废弃）：原来那组按"拥有几个主动技能"现生成按钮，
  技能一多操作区就被撑长。现在改成「行动」组里一个固定的**「释放法术」**按钮，
  点开弹列表（见 `06-物品与技能.md`）。
- 移动组排成方向盘（`PAD_GROUPS`），其余组排成一行。

**各面板职责：**

| 面板 | 放什么 |
|---|---|
| 玩家状态 | 名字、生命与灵性（百分比 + 细进度条）、六项基础属性（**2 行 3 列**，每格是"总值 + 括号明细"） |
| 状态 | 挂着的正面 / 负面状态，**名字是可点的按钮**（点开弹框看效果）。**并排成标签、按内容宽度、装不下自动换行** |
| 玩家背包 | 身上的物品，**名字是可点的按钮**（点开弹框看详情 / 使用 / 打开钱袋笔记本）。**并排成标签、按内容宽度、装不下自动换行**。不限格数。**吃左栏的剩余空间** |
| 地图 | 正方形格子画的地图 |
| 地图点位状态 | **一级。** 玩家脚下这一格的情况：所属区域、房间、坐标、脚下是空地还是门、这扇门通往哪里，以及脚下有没有事件点、旁边站着谁。站在门格上时多一个「进入这扇门」按钮；站在事件点上时多一块「地上」（带互动按钮）；站在人旁边时多一块「旁边的人」（**每人一行：名字 + 类型 · 态度 + 一个「跟某某说话」按钮**）。不列四邻可走方向、也不统计本室出口（原因见下） |
| 二级操作 | **二级。** 点了上面那些按钮之后才出现的东西。现在只有对话：抬头「正在跟某某说话」、他刚说的那一句、进行中的任务进度、一排选项（随便聊聊 / 接受 / 交付 / 结束对话）。没在说话时是一句灰提示 |
| 操作区 | 全部通用指令的按钮，按用途分组 |
| 记事 | 叙事日志，只留最近 400 条，超出自动裁剪 |

#### 玩家状态面板

左栏从上到下：**玩家状态 / 状态 / 玩家背包**。**没有独立的「技能」块** ——
技能换了入口，看总览走操作区「其他」组的**「技艺」**（主动 + 被动一起列）。

**玩家状态：**

| 行 | 内容 |
|---|---|
| 名字 | 角色名 |
| 生命 | 百分比 + 一条细进度条 |
| 灵性 | 百分比 + 一条细进度条 |
| 六项属性 | **2 行 3 列**：力量 智力 精神 / 灵巧 幸运 感知，每格两行 —— 上面**总值**（最终值），下面**括号明细** |

- **没有等级，也没有经验。** 见 `04-数值与成长.md`。
- **神性不列** —— 它参与判定，但玩家看不见。
- 属性受生命惩罚时**总值变色**，让玩家一眼看出"现在被削了"。
- **属性为什么排 2 行 3 列**：省下来的纵向空间留给下面的「状态」和「背包」。

**括号明细**固定四项、顺序固定，四项各一种颜色：

| 顺序 | 项 | 颜色 | 现在是什么 |
|---|---|---|---|
| 1 | 基础值 | 灰（`--fg-dim`） | 角色的底子，六项都是 5 |
| 2 | 被动值 | 绿（`--accent`） | 被动技能的贡献 |
| 3 | 状态值 | 蓝（`--info`） | 挂着的状态贡献（**主动技能也算在这一项**） |
| 4 | 装备值 | 紫（`--gear`） | **现在恒为 0**，装备系统还没做 |

四项显示的是**惩罚后的实际贡献**，所以相加 ≈ 总值（差个四舍五入），玩家能自己核对。
拆解算法和例子见 `04-数值与成长.md` 的「面板怎么显示属性」。

**状态**块挂着的状态名，正面一种颜色、负面另一种，**点名字弹框看效果**。
**多个状态并排成标签**（每个只占自己文字那么宽），一行放不下就换到下一行 ——
一个状态占满一整行太浪费，左栏本来就窄。

**玩家背包**块里每个物品也是一个**可点的标签**（名字，可堆叠的加 `×N`），
点开弹**物品详情**。跟状态块同一套排法：并排成标签、按内容宽度、装不下换行。
**不限格数**，东西再多也只是多换几行。

**货币不在这里。** 钱包不是背包里的一格，是一个数字（见 `06-物品与技能.md`）——
所以背包里不会有"金币 ×30"这种标签，**要看余额得点开钱袋**。

数值规则见 `04-数值与成长.md`，技能、状态、物品的字段见 `06-物品与技能.md`。

#### 弹框

项目里**第一次出现浮层**。六种东西共用一套：
**释放法术 / 技艺 / 状态详情 / 物品详情 / 钱包 / 笔记本**。

- 居中一个方框，后面盖一层半透明遮罩。
- **三种关法**：点右上角「关闭」、点遮罩、按 `Esc`。
- **弹框开着时键盘不给游戏用** —— 免得在列表上按方向键把角色走丢了。
- 关掉之后**不改变焦点**（不把光标塞进输入框），跟其他按钮一致。
- **一次只开一个。** 点物品详情里的「看看里面有多少」是**换**一个弹框
  （先关物品详情，再开钱包），不是叠一个在上面。

> 为什么状态详情也走弹框，而不是"在那一行下面就地展开"：
> 状态块现在是**按内容高度的标签云**，就地展开会把下面的背包顶来顶去；
> 而且四项内容（描述 / 剩余量 / 影响 / 计时）本来就比一行放得下得多。
> 物品详情、钱包、笔记本同理。

**后三种弹框是第 22 轮（背包系统）加的：**

| 弹框 | 怎么开 | 里面是什么 |
|---|---|---|
| 物品详情 | 点背包里的物品标签 / `bag <物品名>` | 标题 + 分类小标签、描述、数量、一个动作按钮（「使用」或打开某个面板） |
| 钱包 | 物品详情里点「看看里面有多少」（钱袋）/ `bag use 钱袋` | 各币种余额，按 `moneyTypes` 逐行画 |
| 笔记本 | 物品详情里点「翻开看看」（笔记本）/ `bag use 笔记本` | 一本"书"：顶上两根**书签**（进行中 / 已完成）点哪根看哪栏；纸面固定默认高度，单栏内容放不下就**翻页** |

**没有钱袋就开不了钱包，没有笔记本就开不了笔记本。** 那两个按钮是物品给的，
没那个物品就没有那个按钮 —— 跟「动作属于哪个东西，按钮就跟着那个东西出现」
是同一条做法（见下）。

**钱包里没有任何币种时**明说一句「里面空空的。」，不是画一块空白 ——
玩家要能区分"我没钱"和"这块界面坏了"。

#### 配色表

颜色全在 `css/theme.css` 的 `:root` 里，**代码里不许写死色值**。语义固定的几个：

| 变量 | 色 | 用在哪 |
|---|---|---|
| `--fg` | 浅灰绿 | 正文 |
| `--fg-dim` | 灰绿 | 次要文字、标签；**属性明细里的「基础值」** |
| `--fg-faint` | 暗灰绿 | 更弱的提示（空闲文案、`idle`） |
| `--accent` | 绿 | 主色：可交互、正面；**属性明细里的「被动值」** |
| `--info` | 蓝 | 中性提示；**属性明细里的「状态值」**、灵性进度条 |
| `--danger` | 红 | 危险、负面状态、生命进度条 |
| `--warn` | 橙 | 警告；**属性被生命惩罚削着的时候** |
| `--quest` | 黄 | 任务相关（地图角标、点位状态里的任务行） |
| `--door` | 橙 | 门格的字 |
| `--gear` | 紫 | **属性明细里的「装备值」**（装备系统还没做，先留着） |
| `--wall` | 深绿 | 墙格背景 |
| `--npc` / `--event` | 灰绿 | NPC / 事件点没写类型色时的兜底 |

> `--gear` 是这次新加的。属性明细四项各要一种颜色，原来那套语义色里
> 只剩「基础」可以用 `--fg-dim`，另外三项借用 `--accent` / `--info` / `--quest`
> 语义都不对（装备跟任务没关系），所以单开一个。

#### 一级 / 二级：为什么把对话选项挪出去

**问题出在"一个位置旁边站着两个人"这个场景上。** 早先对话面板是直接画在
「地图点位状态」里的 —— 一开口，整块「旁边的人」就被对话面板顶掉。
于是跟神秘人说完话之后，**商人从面板上消失了**，想跟他说话得先按「结束对话」。

现在拆成两层：

| 层 | 在哪 | 讲什么 | 什么时候有 |
|---|---|---|---|
| 一级 | 中栏「地图点位状态」 | **旁边有谁**：名字 + 类型 · 态度 + 一个「跟某某说话」按钮 | 站在人旁边就有，**说话时也照列不误** |
| 二级 | 右栏「二级操作」 | **点开之后能做什么**：台词 + 任务进度 + 选项 | 开口之后才有 |

两条硬规矩：

1. **一级区永远列着旁边所有人。** 正在说话的那个只是换个颜色
   （`button.cur`），不从这儿消失。所以点另一个人的按钮就**直接切过去**，
   不用先结束对话。
2. **一级区不报任务进度。** 谁身上有活，地图上那一格右上角的角标已经在说了；
   具体做到哪一步属于"点开才关心"的事，放二级区。

> 「二级操作」这个名字是留了余量的：以后凡是"点了某个东西之后才出现的后续操作"
> 都放这儿，不只对话。所以它不叫「对话面板」。

存档绑定状态（绑没绑磁盘文件）**放顶栏右侧**，不放玩家状态里 —— 它属于"整个程序"的事，不属于角色。

**点位状态只讲"脚下这一格"。** 这里刻意不放两类信息：

| 不放什么 | 为什么 |
|---|---|
| 四邻哪些方向走得通 | **跟地图重复**。走得通的格子地图上本来就能点、鼠标悬停会亮起来，同一件事说两遍 |
| 这间屋子总共几个出口 | **玩家用不上**，是给开发者看的信息；而且跟「通往」容易看串 —— 一个讲这屋子有几扇门，一个讲脚下这扇门通向哪 |

这两项**连计算一起删掉了**，不只是不显示 —— 没人看的东西不值得每次刷新都算一遍。

**「区域」放在最上面一行。** 它回答的是"我在哪一块"，跟下面几行回答的"我在哪一格"
是两回事，所以排在最前面当个大前提。区域的定义见 `05-地图与探索.md`。

**「脚下」那一行只讲脚下这一格，旁边的人另起一块。** NPC 挡路之后，
玩家走不到别人那一格上，所以人只可能在**四邻**。面板那一块因此叫「旁边的人」，
不叫「脚下的人」。

**动作属于哪个东西，按钮就跟着那个东西出现。** 这条做法在本项目里反复用到：

| 东西 | 在哪一层 | 什么时候出现 | 出现什么 |
|---|---|---|---|
| 门 | 一级 | 站在门格上 | 「进入这扇门」按钮 |
| 事件点 | 一级 | 站在它上面（且它写了互动效果） | 一块「地上」+ 一个互动按钮（文字取自素材的 `hint`） |
| 人 | 一级 | 站在人旁边 | 「跟某某说话」按钮（正在说话的那个换高亮，其余照列） |
| 对话 | **二级** | 已经开口了 | 一排选项：随便聊聊 / 接受任务 / 交付任务 / 结束对话 |
| 物品 | **二级** | 点开背包里的物品标签 | 一个动作按钮：有 `use` 就是「使用」，有 `panel` 就是打开那个面板 |
| 状态 | **二级** | 点开左栏状态块里的状态名 | 状态详情（描述 / 剩余量 / 影响 / 计时） |

没站在门上、没站在东西上、没站在人旁边时，那些按钮**根本不存在**，
也就点不出"条件不成立的动作"。物品和状态那两个按钮同理 ——
**没有钱袋就没有"看看里面有多少"**，不是"画出来但点了没反应"。
**一级的按钮画在一级区，点开之后的画在二级区**，两层不混着放。

**「对话」是一排选项，一个任务就是一个选项。** 同一个 NPC 身上可以同时挂着
普通对话、可接的任务、能交的任务，它们并列成一排，各点各的。
NPC 与任务的数据结构、对话的完整规则见 `09-NPC与任务.md`。

### 地图画法

- 地图用**正方形格子**拼，一格一个字符
- 字符约定：`#` 墙、**门格画一个「门」字**、**NPC 那一格画它的图标字**、
  **事件点那一格画它的图标字**（`hidden` 且还没触发过时**只留空框、不画字**）、
  **玩家那一格画角色名的第一个字**；**空地不画任何字符**（不是点，就是空的）
- **门格只换字形，不换定义**。门在素材里是 `rooms[].doors` 里的一条（键是 `"x,y"`），
  `tiles` 里根本没有 `+` 这个字符 —— `+` 从来只是渲染时画上去的。
  所以改字形不影响存档、不影响 `doorAt()` 判定。字形收在 `js/ui.js` 的 `DOOR_GLYPH`，
  想换只改那一行。
- 门格的「门」是满宽汉字，照统一字号 `--fs` 那么大会贴着格子边，
  所以单独缩到格子的 0.7；**橙色底块照旧铺满整格**，看起来就是"方块里写着门"
- **NPC 那一格画的是它自己的图标字（`glyph`），不是它的名字** ——
  名字往往两三个字，格子只放得下一个。颜色来自类型表，缩到格子的 0.7；
  外面套一圈**类型色的细框**（跟玩家格的绿框同一个做法，`inset` 阴影画的，不占布局）；
  身上有活可干时，右上角多一个小方块角标（用 `::after` 画，不额外塞元素）
- **NPC 挡路，所以玩家不可能跟它同一格。** 走不过去时会说「某某挡在前面，过不去」，
  跟撞墙分开说 —— 都说"墙"会让玩家以为地图画错了
- **玩家标记外面套一圈绿框**，不用通用的 `@`。理由有两个：
  一是 `@` 看不出是谁，用自己的名字首字一眼就是"我"；
  二是将来地图上出现别的角色、或者某个东西正好也叫这个字时，
  有框才分得开。框用 inset 阴影画，完全不影响布局（格子宽高不会被挤动）。
  汉字是满宽的，所以玩家格的字号缩到格子的 0.62，留出边距不顶框。
- 格子边长写成 CSS 变量 `--cell`，字号写成 `--fs`，两个都由 `js/ui.js` 按面板大小算出来
- 墙格**用背景色铺满整格，不画 `#` 字形**。相邻墙格连成一片，看起来才是"墙"，
  而不是一排井号
- 每行是一个 `display:flex` 的行块，格子是定宽定高的块。**不用行内块 + 行高**：
  行内块要跟行盒的基线对齐，行盒会比格子高出一两个像素，七行叠起来就顶出一条滚动条

**格子大小自适应面板**，有上下限：

| 变量 | 值 | 为什么 |
|---|---|---|
| `CELL_MIN` | 16 px | 再小字就看不清了 |
| `CELL_MAX` | 56 px | 再大地图就散架了，不像一张图 |
| `FS_OF_CELL` | 1.0 | 字号 = 格子边长，字形高度约占格子的七成 |
| `WIDTH_FILL` | 0.86 | 字宽最多占格子的八成六，左右各留一点空 |

取 `min(面板宽 ÷ 列数, 面板高 ÷ 行数)`，再夹在上下限之间 —— 小地图放大到填满面板，
大地图缩到看得清为止。用 `clientWidth / clientHeight` 量可用空间，**不用
`getBoundingClientRect()`**：前者扣掉了滚动条，后者不扣，不扣会陷入
"出现滚动条 → 可用宽度变小 → 还是溢出" 的死循环。

> 为什么不用"东西南北"：网页是二维的，玩家看到的就是上下左右。方向词一律用上下左右，
> 门名也照此命名（"上面的铁门"，不是"北门"）。

### 输入方式

**四条路，同一套指令表。** 指令表是 `js/main.js` 里的 `CMDS`，是唯一的事实来源，
加一条指令只改那一处。四条路都只是"替玩家说出这条指令"：

| 路子 | 怎么用 | 适合 |
|---|---|---|
| 键盘 | 方向键 / WASD / 小键盘直接走 | 平时走路，主力 |
| 操作区 | 点方向盘和按钮 | 鼠标流、想不起来指令时 |
| 地图 | 点玩家相邻的格子 | 鼠标流、想走哪个方向就点哪个 |
| 指令输入 | 按 `/` 或回车，打字，再回车 | 存档、帮助这类非移动操作 |

点位状态面板里那些**上下文按钮**（「进入这扇门」「喝一口」「跟某某说话」「接受：走十步」……）
也是同一条路：它们把子命令写进 `data-arg`，点下去走的还是 `CMDS` 里那条指令。
所以加一条指令，键盘、操作区、面板按钮全都跟着有。

> 例外：`enter`、`talk`、`use` **不在操作区里**。它们各自绑在门、人、事件点身上，
> 只有条件成立时（站在门上 / 站在人旁边 / 站在事件点上）点位状态面板才会画出那个按钮；
> 点开之后的**二级**东西（现在只有对话选项）画在右栏的二级操作里。
> 不给它们通用按钮，就不会出现"没站在门上却点得动进入"的尴尬。
> → 这是本项目的一条通用做法：**动作属于哪个东西，按钮就跟着那个东西出现**，
> 不要什么都往操作区里堆。

#### 走路模式 / 命令模式

键盘只有一个，走路用 `w a s d`，而存档指令是 `save`、向下是 `s` ——
同一个键不可能既是"走"又是"打字"。所以分两个模式，切换只要一个键：

| 模式 | 怎么进 | 键盘归谁 | 输入栏样子 |
|---|---|---|---|
| 走路模式（默认） | 开局就是；按 `Esc` 或执行完指令自动回来 | 归游戏 | 边框暗、提示语是"↑↓←→ / WASD 走路" |
| 命令模式 | 按 `/` 或回车；点输入栏也算 | 归输入框 | 边框亮绿、提示语是"输入指令" |

细节：

- **`Esc` 退出命令模式**，输入框里的内容一并丢掉。
- **指令打错时留在命令模式**，方便接着改，不用再按一次 `/`。
- **空回车 = 退出命令模式。**
- **模式只是个外观。** 按键归谁管看的是 `document.activeElement`，
  所以边框颜色就算慢半拍，键盘行为也不会错。
- **焦点只在输入框和按钮之间挪。** 以前每次执行完指令都把光标塞回输入框，
  结果方向键全被输入框吃掉，只在框里左右移光标 —— 现在执行完就摘掉焦点。

#### 键盘按键表

按 `e.code`（物理键位）认键，**不按 `e.key`**：开着中文输入法时 `e.key`
可能变成别的字符，`e.code` 永远是物理键位。

| 键 | 作用 |
|---|---|
| `↑` `↓` `←` `→` | 上下左右走一格 |
| `W` `A` `S` `D` | 同上 |
| 小键盘 `8` `2` `4` `6` | 同上 |
| 小键盘 `5` / `.` / 空格 | 进门（`enter`） |
| `/` 或回车 | 进命令模式 |
| `Esc` | 退出命令模式 |

**按住不放可以连着走**，但两次之间至少隔 110 ms（`REPEAT_MS`）——
不限速的话每走一步写一行日志，按住一秒就刷屏。

#### 指令表

| 指令 | 别名 | 分组 | 作用 |
|---|---|---|---|
| `up` | `上` `w` | 移动 | 向上移动一格 |
| `down` | `下` `s` | 移动 | 向下移动一格 |
| `left` | `左` `a` | 移动 | 向左移动一格 |
| `right` | `右` `d` | 移动 | 向右移动一格 |
| `enter` | `进入` | —（绑在门上） | 站在门上时进入该门 |
| `talk` | `对话` `说话` | —（绑在人身上） | 跟旁边的人说话；对话选项通过子命令选（见下） |
| `cast` | `法术` `技能` | **行动** | 不带参数 = 弹出**法术列表**；带参数 = 直接释放（`cast 凝神` / `cast skl_focus`） |
| `look` | `l` `查看` | 行动 | 重新描述当前房间 |
| `save` | `存档` | 存档 | 存档（本地存储 + 已绑定的磁盘文件） |
| `load` | `读档` | 存档 | 读取存档 |
| `export` | `导出` | 存档 | 导出为 `.json` 文件下载 |
| `import` | `导入` | 存档 | 从 `.json` 文件导入 |
| `bind` | `绑定` | 存档 | 绑定一个磁盘存档文件，清缓存也不丢 |
| `arts` | `技艺` | 其他 | 弹出**技艺总览**：已学的全部技能（主动 + 被动）带描述 |
| `help` | `?` `帮助` | 其他 | 列出全部指令 |
| `clear` | `清屏` | 其他 | 清空记事 |
| `buff` | `状态` | —（绑在状态上） | 弹出某个状态的详情（`buff 凝神` / `buff st_focus`） |
| `bag` | `背包` `物品` | —（绑在物品上） | 不带参数 = 在记事里列一遍背包；带参数 = 打开这个物品的详情（`bag 钱袋`）；`bag use 钱袋` = 直接用它 |
| `reset` | `重开` | — | 删除存档重新开始，需 `reset yes` 二次确认 |

四条约定：

1. **`reset` 不出现在操作区里**，只能打字。删档是不可逆的，不给按钮，避免手滑。
2. **`enter` / `talk` / `use` / `buff` / `bag` 也不出现在操作区里。** 它们是门、人、
   事件点、状态和物品自己的动作，只有条件成立时（站在门上 / 站在人旁边 /
   站在事件点上 / 身上挂着这个状态 / 身上有这个物品）才由对应的面板临时画出按钮。
   其中 `enter` 和 `use` 的按钮就画在一级区；
   `talk` 的**一级**按钮（「跟某某说话」）也在一级区，点开之后的**二级**选项画在右栏的二级操作里；
   `buff` 的按钮就是左栏「状态」块里那个可点的状态名；
   `bag` 的按钮就是左栏「背包」块里那个可点的物品名。
   不给它们通用按钮，就不会出现"没站在门上却点得动进入"的尴尬。
   → 这是本项目的一条通用做法：**动作属于哪个东西，按钮就跟着那个东西出现**，
   不要什么都往操作区里堆。
3. **别名不抢 `look` 的 `l`。** 移动一律用方位词（`上` / `w`），不用 `l` / `r`，
   免得跟"查看"和将来可能的指令打架。
4. **移动类指令标 `quiet`，不回显。** 走一步写两行（`> up` + "你向上走了一步"）
   会把日志刷满。手打的指令仍然回显 —— 玩家得看见自己打了什么。
   对话的各个子命令也标了 `quiet` —— 面板上的按钮点一下就回显一行 `> talk chat`，
   记事会被点花。

> `行动` 分组现在有 `查看` 和 `释放法术` 两条。
> 留着不合并，是因为以后加战斗时，攻击这些也归这里，那才是它真正的主场。
>
> **`cast` 不带参数时弹列表、带参数时直接放** —— 同一个指令两种行为。
> 这样"点按钮"（不带参数）和"打字快捷方式"（带参数）共用一条指令，
> 不用为列表再开一个新指令。

#### `talk` 的子命令

`talk` 是个"带参数"的指令 —— 面板上的按钮就是把子命令写进 `data-arg` 传回来的：

| 指令 | 作用 |
|---|---|
| `talk` | 跟旁边的人说话（旁边只有一个人才行，多人会提示点哪一行） |
| `talk <npcId>` | 跟指定的那个人说话 |
| `talk chat` | 换一句普通台词 |
| `talk accept <questId>` | 接受任务 |
| `talk deliver <questId>` | 交付任务 |
| `talk bye` | 结束对话 |

完整规则见 `09-NPC与任务.md` 第三节。

#### `cast` 的子命令

`cast` 只接受**一个**参数：技能 id 或技能名（玩家多半打名字）。

| 指令 | 作用 |
|---|---|
| `cast 凝神` | 用一次「凝神」 |
| `cast skl_focus` | 同上，按 id |

- **只有主动技能能"用"。** 被动技能一直生效着，没有可用的动作，打了会提示。
- 找不到 / 不拥有 / 不是主动技能，各给一句不同的提示，**别都说"没有这个技能"** ——
  那会把"我确实有但用不了"说成"我没有"。
- 用完挂上哪个状态由素材的 `applies` 决定，见 `06-物品与技能.md`。

#### `buff` 的子命令

| 指令 | 作用 |
|---|---|
| `buff` | 身上只有一个状态时就打开它，多个会提示点哪一行 |
| `buff 凝神` | 打开这个状态的详情 |
| `buff st_focus` | 同上，按 id |

- 找不到 / 没挂这个状态，各给一句不同的提示。

#### `bag` 的子命令

| 指令 | 作用 |
|---|---|
| `bag` | 在记事里列一遍背包（"身上带着：钱袋、清心草 ×3。"） |
| `bag 钱袋` | 打开这个物品的详情弹框 |
| `bag itm_purse` | 同上，按 id |
| `bag use 钱袋` | **直接用一次**，跳过详情框 |

- **`bag use` 是"对这个物品做它能做的事"**，具体做什么由素材决定：
  有 `use` 就跑效果（**并消耗一个**），有 `panel` 就打开那个面板（**不消耗**）。
  所以 `bag use 钱袋` 打开的是钱包，`bag use 清心草` 是吃掉一株。
- 名字重名（两个物品同名）时报错并提示用 id，**不要随便挑一个**。
- 找不到 / 身上没有，各给一句不同的提示 —— 别都说"没有这个物品"。
- **背包是空的**时 `bag` 说一句「身上什么也没有。」，不是列一块空白。

> `bag use` 这个名字稍微有点不贴切（打开钱包不叫"用"），但**玩家看到的是按钮**，
> 打字党用一条指令解决"对这个东西做点什么"更省事。按钮的 `data-arg` 也统一走它。

#### 操作区为什么不再有「技能」组（已废弃的写法）

原来操作区里有一组动态的「技能」按钮 —— 拥有几个主动技能就有几个。
问题：**技能一多操作区就被撑长**，而且那组按钮跟"行动"里的东西语义上是一类的。
现在改成**行动组里一个固定的「释放法术」按钮**，点开弹列表。

> 代价：释放多了一步（点按钮 → 点列表里的「释放」）。
> 换来的是操作区高度固定，不受技能数量影响。打字仍然可以一步到位：`cast 凝神`。

#### 操作区的方向盘

移动组的四个键排成方向盘（上在上一行正中，左中右在下一行），不排成一行 ——
按物理位置摆，手不用看就知道哪个是哪个。由 `CMDS` 里的 `group` 字段加
`PAD_GROUPS` 决定，不是写死在 HTML 里。

## 已废弃

### 方向词用 `north` / `south` / `east` / `west`

废弃于 P0 骨架第一次跑起来之后。原因：网页是二维的，玩家看到的是上下左右，
"向北走"要额外在脑子里做一次映射。改成 `up` / `down` / `left` / `right`。
门名同步从"北门"改成"上面的铁门"。

### 操作按钮排在输入框下面

废弃于同一次调整。原因：按钮会随玩法变多，堆在输入框下方会把输入框越挤越远。
改成右栏独立面板，内部滚动。

### 主界面限制宽度 1080px、居中显示

废弃于第二次界面调整。原因：两边留白浪费屏幕，地图也没地方长。
改成铺满整个窗口，左右两栏用 `clamp()` 限宽、中栏吃掉剩余宽度。

### 界面只有"地图 / 状态 / 操作"三块，记事与输入行占满全宽

废弃于第二次界面调整。改成左右两条窄栏 + 中间主区的结构：
左栏放玩家自己的东西，右栏放操作与预留，地图和点位状态并排在中栏上排，
记事横跨这两块，输入行只在中栏底下。好处是每块地方都有明确的归属，
以后加背包、加装备栏、加小地图都有位置放，不用再动骨架。

### 地图格子固定尺寸，不随面板变

废弃于同一次调整。原来格子边长只跟字号挂钩，面板再大地图也只是缩在正中间一小块。
改成按面板大小自适应（`min(宽÷列, 高÷行)`，夹在 16–56px 之间）。

### 每执行完一条指令就把焦点塞回输入框

废弃于加入键盘控制时。原因：焦点一直在输入框里，方向键和 WASD 全被输入框吃掉，
按下去只在框里左右移光标，根本走不了路。改成执行完就摘掉焦点，回走路模式。

### 移动的四个按钮排成一行

废弃于加入键盘控制时。原因：排成一行要读字才知道哪个是哪个。
改成方向盘布局，按物理位置摆。

### 操作区的按钮一律回显指令（`> up`）

废弃于加入键盘控制时。原因：键盘走路一秒能走好几步，每步两行日志，
记事瞬间被 `> up` 刷满。改成移动类指令标 `quiet` 不回显；手打的仍然回显。

### `进入` 按钮放在操作区的「行动」组里

废弃于把动作绑到东西上那次调整。原因：`进入` 只有在站在门格上时才有意义，
放在通用操作区里，没站在门上时它也一直在那儿、点了只会报"你脚下没有门"。
改成绑在门上：站在门格上时，点位状态面板里才出现「进入这扇门」按钮。

### 玩家在地图上画成 `@`

废弃于把玩家标记改成名字首字那次调整。原因：`@` 看不出是谁，
同屏出现别的角色时更分不清。改成画角色名的第一个字，外面套一圈绿框。

### 门在地图上画成 `+`

废弃于把门的字形改成「门」字那次调整。原因：`+` 是个纯符号，
跟墙、跟以后要加的东西（怪物、道具、机关）容易撞脸，新人第一眼也看不出那是门。
改成门格画一个「门」字，底下的橙色块照旧。

注意这次**只动字形，没动门的定义**：门仍然是素材 `rooms[].doors` 里的一条，
判定一律走 `G.data.doorAt()`，跟画什么字无关。字形收在 `js/ui.js` 的 `DOOR_GLYPH` 一处，
以后想换成别的字或图标只改那一行。

### 点位状态里列「可走」和「本室出口」

废弃于精简点位状态那次调整。

- 「可走」：跟地图重复。走得通的方向，地图上那一格本来就能点、悬停会亮，
  再列一行是同一件事说两遍。
- 「本室出口」：是给开发者看的信息，玩家用不上；而且跟「通往」容易看串。

两项**连计算一起删了**（`js/ui.js` 里那段四邻遍历和 `edgeExits()` 整个函数都去掉了），
不只是从界面上藏起来 —— 没人看的东西不值得每次刷新都算一遍。
`dir.up` / `dir.down` 这类方向文案保留，`js/world.js` 命名门的时候还在用。

### 点位状态里的「脚下的人」

废弃于 NPC 挡路那次调整。

原因：NPC 不挡路时玩家能走到它那一格上，所以用「脚下的人」说得通。
改成 NPC 算障碍物之后，人只可能在**四邻**，那一块跟着改叫「旁边的人」，
判断也从"脚下这一格有没有人"换成 `G.data.npcsNear()`。

同时把「跟某某说话」按钮挪进这一块 —— 没站在人旁边时它根本不存在。

### 右栏下面那块叫「预留区域」

废弃于加入二级操作那次调整。

原因：那块地方本来只是一句占位文字，没人知道要拿来干什么。现在明确了用途 ——
**放"点了某个东西之后才出现的后续操作"**，所以改叫「二级操作」，
并且**跟操作区换了位置**（二级操作在上、操作区在下）。

换位置的理由：二级操作的内容会随情况变长（对话选项一多就长），
让它吃剩余空间、内部滚动；操作区是固定的那几组通用指令，按内容高度就好。
反过来放的话，选项一多就会把操作区挤下去。

### 对话面板画在「地图点位状态」里

废弃于同一次调整。

原因：一开口，整块「旁边的人」就被对话面板顶掉了。旁边站着两个人时
（比如神秘人和商人），跟其中一个说完话，另一个就从面板上消失，
想跟他说话得先按「结束对话」。**而这个"旁边站着两个人"正是这次要解决的场景。**

改成一级 / 二级两层：一级区（中栏）永远列着旁边所有人，正在说话的那个只换高亮；
台词、任务进度、选项全挪到右栏的二级操作里。点另一个人的按钮就直接切过去。

顺带把**任务进度行**也从一级区拿掉了 —— 谁身上有活，地图那一格右上角的角标
已经在说；做到哪一步属于"点开才关心"的事，归二级区。

### 操作区里的「技能」分组

废弃于加入「释放法术」/「技艺」那次调整。

原因：那组按钮是按"拥有几个主动技能"现生成的，**技能一多就把操作区撑长**；
而且它跟「行动」里的东西语义上是一类的（都是用一下会发生点什么）。
现在改成「行动」组里一个固定的**「释放法术」**按钮，点开弹列表。

顺带：操作区的分组从 `移动 / 行动 / 技能 / 存档 / 其他` 变成
`移动 / 行动 / 存档 / 其他`，**「技能」不再是分组名**。
技能本身没消失，只是换了入口 —— 看总览走「其他」组的「技艺」。

### 玩家状态的属性排成 6 行 1 列

废弃于同一次调整。

原因：六项属性一人一行占掉大半个面板，把下面的「状态」块挤得只剩两行。
改成 **2 行 3 列**，每格两行（总值 + 括号明细），省下来的纵向空间给状态。

顺带把左栏"吃剩余空间"的那块从**玩家背包**换成**状态** ——
状态的数量是会变的，背包现在还是空的，余量给会变的那块才有用。

> **⚠️ 这一段已被后面那次调整推翻，见下条。** 留着是因为"余量给会变的那块"
> 这个理由本身没错，错的是它假设了状态块需要靠余量撑开。

### 左栏的「技能」块

废弃于第 20 轮之后的界面调整。

原因：技能**换了入口**之后这一块就重复了 —— 主动技能在「行动 → 释放法术」里，
主动 + 被动总览在「其他 → 技艺」里，而且弹框比左栏那一小块宽得多、
能写描述。左栏留着它只是白占一行高度。

**被动技能没有因此看不见** —— 技艺弹框里列的就是主动 + 被动。

顺带把左栏从四块收成三块：**玩家状态 / 状态 / 玩家背包（预留）**。

### 状态块占满一整行、且吃掉左栏剩余空间

废弃于同一次调整。

原因两条：

1. **一个状态占满一整行太浪费。** 左栏本来就窄，状态名通常两三个字，
   一行放一个的话右边全是空白。改成**并排成标签**（每个只占自己文字那么宽），
   一行放不下自动换行 —— 状态多了自己往下长，比"一行一个"省一半高度。
2. **"状态吃剩余空间"这个决定跟着作废了。** 状态块现在按**内容高度**排
   （`minmax(0, auto)`），余量还给**玩家背包**。原来的理由是"余量给会变的那块"，
   现在这个需求由**并排换行**解决了，不需要靠拉伸来容纳。

配套：`#buffs` 从 `display: grid` 单列改成 `display: flex; flex-wrap: wrap`，
按钮去掉 `width: 100%`、加上 `white-space: nowrap`。

### 左栏「玩家背包」块上挂着「预留」小标签

废弃于背包系统上线那次调整（第 22 轮）。

原因：那块地方做出来了 —— 物品并排成标签、点开有详情框、能用能开面板。
还挂着「预留」两个字会让人以为这儿还没做完，而**空背包和"没做的背包"
是两回事**：前者该说「身上什么也没有。」，后者才该标「预留」。

配套：`#bag-panel` 的标题去掉 `<span class="tag">预留</span>`，
占位文字 `还没有东西。` 换成正式的空状态文案。
