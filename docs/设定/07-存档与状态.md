# 07 存档与状态

> 状态：已定
> 负责：存档怎么落盘、状态对象长什么样、旧存档怎么迁移
> 不负责：数值含义（见 04）、物品与技能字段（见 06）

---

## 存档机制（已定）

| 层 | 机制 | `file://` 可用性 | 定位 |
|---|---|---|---|
| L1 | 浏览器本地键值存储，自动写 | 可用 | 顺手，清缓存会丢 |
| L2 | 绑定磁盘 `.json` 文件 | 可用，需一次授权 | 清缓存不丢 |
| L3 | 导出 / 导入 `.json` | 可用 | **给别人玩的主力**，全浏览器通用 |
| L4 | base64 存档码 | 可用 | 微信直接发一段文字 |

自用版 L1 + L2 + L3 全开；分享版把 L3 做成界面上显眼的按钮，L2 作为可选。

### 硬性约定

- **存档 key 必须带命名空间**，如 `moyu.save.v1`。所有 `file://` 页面共享同一份本地存储，不加命名空间会和以后写的其它小游戏串档。
- **存档内容是纯数据**，不含函数、不含 DOM 引用，保证 `JSON.stringify` 可以直接序列化。
- **存档顶层必须带 `v` 字段**（格式版本）。自用工具必然反复改字段，没有版本号就是改一次废一次档。
- **跨浏览器、跨设备只能靠 L3 / L4。** Chrome 里的档 Edge 读不到，这是浏览器存储模型决定的，不是实现问题。

### 版本迁移策略（原则）

读档时先看 `v`：

- 等于当前版本 → 直接用
- 低于当前版本 → 依次跑迁移函数链
- 高于当前版本 → 拒绝加载并提示

迁移函数只增不改，废弃的不要删。

## 状态结构（已定）

```js
G.state.data = {
  v: 6,                                    // 存档格式版本
  createdAt: 1695000000000,                // 建号时间
  rng:   { seed: 123456, cursor: 0, step: 0 },
  player: {
    name: '摸鱼者',
    hp: 100, hpMax: 100,                   // 生命，百分比值
    ess: 100, essMax: 100,                 // 灵性，百分比值
    base: { str: 5, int: 5, spr: 5, dex: 5, luk: 5, per: 5 },
    div: 0,                                // 神性，面板不显示
    skills: ['skl_ironbone', 'skl_focus'], // 拥有的技能 id（见 06）
    statuses: [ { id: 'st_poison', left: 8 } ]   // 挂着的状态 + 剩余量
  },
  world: {
    roomId: 'room_hall',
    x: 4, y: 3,
    visited: {},                            // roomId -> true
    flags: {}                               // 剧情标记
  },
  quests: {},                               // 任务 id -> { state, progress, times }
  events: {},                               // 事件点 id -> { times }
  items:  {},                               // 物品 id -> { count }（见 06）
  wallet: {}                                // 币种 id -> 数量（见 06）
}
```

### 版本历史

| 版本 | 改了什么 | 迁移怎么处理 |
|---|---|---|
| v1 | 初版 | — |
| v2 | 加了 `quests` 字段（任务进度，见 `09-NPC与任务.md`） | 补一个空对象即可 |
| v3 | 任务改成**接取制**：多了一个 `times` 字段，"没有记录"的含义从"进行中"变成"**可接**" | **不用动数据** —— 结构没变，`times` 缺了按 0 算；v2 存档里没有记录的任务本来就只有玩家一步没走过的那些，正好对应"还没接"。`migrate()` 里留了一段空的 v2→v3，是为了把改动点记在案上 |
| v4 | 加了事件点的触发次数（`events` 字段，见 `10-事件点.md`） | 补一个空对象即可 —— "没有记录" = 一次都没触发过 |
| v5 | **玩家状态整体换新**（见 `04-数值与成长.md`）：删掉等级 / 经验 / 攻防速 / 法力 / 金币，换成生命·灵性百分比 + 六项基础属性 + 神性 + 技能 + 状态 | **不做迁移，直接拒绝**（见下） |
| v6 | 加了**背包**（`items`）和**钱包**（`wallet`），见 `06-物品与技能.md` | **补两个空对象即可，旧档能用** —— "没有记录" = 没有这个东西 / 这个币种余额为 0 |

> **v6 为什么不像 v5 那样拒绝**：v5 是**把旧字段整个换掉**（`lv` / `mp` / `gold` 全删，
> `hp` 的语义从"20 点"变成"100%"），对不上就是真对不上。
> v6 是**纯新增两张表**，`player` / `world` / `quests` / `events` 一个字段都没动 ——
> 旧的 v5 存档补两个空对象之后语义完全正确（没东西、没钱，本来就是这样）。
> 能迁移就迁移，别动不动就让人重开。

### v5 为什么不迁移

`player` 里除了 `name`，**一个字段都没有对应关系**：
`lv` / `exp` / `expNext` / `mp` / `atk` / `def` / `spd` / `gold` 全删了，
`hp` 从"20 点"变成"100%"，语义都不一样，硬映射只会造出一份谁也说不清的档。

所以读到 v1–v4 的存档**一律拒绝加载**，回到创建角色页重开。
只有自己的档，重开比写一段假的映射便宜，而且不会留下错误的数据。

`world` / `quests` / `events` 三个字段其实没变 —— 但既然要重开，就不为它们单独开后门，
不然会出现"半新半旧"这种更难排查的状态。

> **v5 存档现在是能用的。** v6 加了 `items` / `wallet` 两张新表，
> 迁移就是补两个空对象 —— 见上面版本历史表里 v6 那一行。
> 「拒绝」只针对 v1–v4，别把这条规则顺手扩到 v5。

### 关于 quests 字段

- 每条记录是 `{ state, progress, times }`：
  `state` 取 `'available'` / `'active'` / `'done'`，`progress` 是已推进的步数，
  `times` 是交付过几次（可重复任务用它记完成次数）。
- **「没有记录」= `available`（可接）。** 所以旧存档不用迁移就能直接用。
- **故意不清理指向已删任务的记录。** 任务临时下线再加回来时，进度还在；
  多出来的键不占地方也不影响渲染。
- 字段存在 ≠ 任务存在。任务的定义在 `data/quests.js`，存档里只放进度。
- **对话状态不进存档。** 正在跟谁说话、他刚说了哪一句都是瞬时的，
  关掉游戏再打开不该还在跟人说话（见 `09-NPC与任务.md` 第三节）。

### 关于 items 与 wallet 字段

- `items` 是 `物品 id -> { count }`：`count` 是持有数量。
- **「没有记录」= 没有这个东西。** 所以旧存档不用迁移就能直接用，
  跟 `quests` / `events` 是同一个约定。
- **唯一物品（`stack: false`）的 `count` 恒为 1。** 字段照写 ——
  统一成 `{ count }` 之后，读取的地方不用分两种情况。
- **故意不清理指向已删物品的记录。** 物品临时下线再加回来时，数量还在
  （跟 `quests` 同一个理由）。
- **字段存在 ≠ 物品存在。** 物品的定义在 `data/items.js`，存档里只放数量。
- `wallet` 是 `币种 id -> 数量`，**货币不占背包格**（见 `06-物品与技能.md` 的「货币」）。
- **「没有记录」= 余额为 0。** 也是一样，不用迁移。
- **余额不会是负数。** 扣钱扣到 0 为止（`G.items.addMoney` 里夹住），
  所以存档里不会出现 `-5` 这种数。

> 两张表都是"照搬，不清理"。`normalize()` 里就两行 `raw.items || {}` ——
> 别在这里加"检查物品 id 还在不在"的逻辑：那会让素材改名等于删档，
> 而多出来的键既不占地方也不影响渲染。

### 关于 player 字段

- `hp` / `hpMax`、`ess` / `essMax` 存的是**百分比值**（0–100），不是点数。
- `base` 是六项**基础值**，惩罚和技能都**不写回**这里。
- **最终属性不存**，每次按 `04-数值与成长.md` 的公式现算 ——
  存档里就不会出现"改了技能忘了同步属性"这种不一致。
- `skills` 只存 id，技能定义在 `data/skills.js`（跟 quests 一个思路）。
- `statuses` 存 `{ id, left }`，`left` 是剩余量（按状态的 `unit` 解释）。没记录 = 没挂着。
- `div`（神性）参与判定但不显示，所以**必须在存档里**，不能算出来。

### 关于 rng 的三个字段

| 字段 | 用途 |
|---|---|
| `seed` | 原始种子，只用于显示和"重开同一局"，**恢复时不用它** |
| `cursor` | mulberry32 的当前内部状态。**恢复随机流用这个，O(1)，不需要重放** |
| `step` | 已推进步数，排查问题用 |

只存 `seed` 是错的：那样读档后随机序列会从头开始，玩家能靠反复读档刷出同一个结果。
存 `cursor` 比存"种子 + 步数"更好，因为恢复不需要重放 step 次。

### 状态是纯数据

不含函数、不含 DOM 引用、不含 `undefined`。保证 `JSON.stringify(G.state.data)` 就是完整存档。

## 落盘位置

| 内容 | 存放位置 | key |
|---|---|---|
| 存档数据 | 浏览器本地键值存储 | `moyu.save.v1` |
| 磁盘文件句柄 | IndexedDB | 库 `moyu` / 表 `handles` / 键 `saveFile` |

句柄只能放 IndexedDB——本地键值存储存不了 `FileSystemFileHandle` 对象。
