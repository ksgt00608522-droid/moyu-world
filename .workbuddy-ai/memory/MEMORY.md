# 魔鱼世界 · 项目长期约定

## 项目性质

复古网页文字打怪 RPG。老程序员自用 + 分享给朋友。
运行期零 AI、零外部网络；AI 只在开发期参与。

---

## 文档纪律（最高优先级，每次开发必须遵守）

1. **`docs/设定/` 是唯一事实来源。代码服从文档，不是文档描述代码。**
2. 动任何代码前，先读 `docs/设定/00-索引.md` 找到对应分类，再读那份文档。**不读不写。**
3. 讨论中定下的新规则，**当场写进对应分类文档**，不允许只留在对话里。
4. 文档与代码冲突时以文档为准；确实要改规则，先改文档，再改代码。
5. 一个分类一个文件，不混写。
6. 废弃的决定标记「已废弃」并写明原因，不删。
7. **删字段 / 改字段名时，必须 grep 一遍 `data/` 和 `tools/`。**
   只改 `js/` 是不够的 —— 素材和测试里可能还引用着它，而且**引用错了不会有任何反馈**。
   踩过的实例：`gold` 在 v5 删了，可 `data/events.js` 的铜钱事件还写着
   `"set": { "player.gold": "+1" }`，格式合法、`applyEffect` 又是空壳，
   于是那条效果永远静默失效、界面上完全看不出来；冒烟里还有一条
   `player.gold === goldBefore` 的**恒真断言**（两边都是 `undefined`）陪它一起躺着。
   → 现在 `validate.mjs` 拿字段白名单拦 `set` 的键，但**别的字段还没这层保护**。

原因：长对话会稀释注意力，导致凭印象写出与早先设定冲突的代码，而这种冲突往往要等游戏跑起来才暴露。

## 技术硬约束（不可违反）

1. **不用 ES Module。** `file://` 下 import / export 全部失效。用普通 `<script src>` + 全局命名空间 `G`。
2. **数据文件是 `.js` 不是 `.json`。** `fetch` 本地 json 会抛 TypeError。写法：`G.data.x = [ ...纯 JSON 字面量... ];`
3. **开发环境 = 交付环境 = 直接双击 `file://`。** 禁止引入本地服务器。
4. 所有文件 UTF-8 无 BOM，HTML 显式声明 charset。
5. **零依赖。** `node_modules` 必须保持不存在，只用 Node 内置模块。
6. 交付形态是**单个 HTML 文件**，双击即玩，零安装。

## 开发习惯

- 逻辑与表现分离：产出事件列表的模块不碰 DOM。
- 随机数走统一种子源，禁止直接调用 `Math.random()`。
- 数值写在 `data/`，公式写在 `js/rules.js`。
- 素材之间引用只走 ID，永不内联对象。
- 打包产物交付前，用 `tools/probe.mjs` 无头验证一次。
- **改同一个文件的多处时，分成多条消息改**（或者用一次编辑覆盖整段）。
  一条消息里发两个编辑改同一个文件，两个都基于原始内容算新内容再写回，
  **后写的把先写的盖掉，但两个都报成功** —— 会静默丢改动，直到跑测试才暴露。
- **加新内容时要回头看测试用了哪些格子 / 哪些路线。**
  这一轮事件点先放在 `(1,1)` 和 `(6,1)`，正好撞上冒烟里"空地是空白"用的格子和
  "往右走三步"的路径；上一轮 NPC 也把移动路线带偏过。素材位置不是随便挑的。
- **下层模块要给上层"留个钩子"，不要反向调用。** 加载顺序即依赖顺序，
  `save` 排在 `ui` / `world` / `main` 前面。
  **但钩子失去订阅者时要连钩子一起删**（第 20 轮）：`G.save.onLoaded(fn)` 当初是为
  "读档后重画操作区"加的，后来操作区内容跟角色解耦（技能组废弃），
  那个回调做什么都不变 —— 破坏点「读档之后要重画操作区」**再也变不红**，
  留着就是永远绿的假保障。于是 `afterLoad` / `onLoaded` / `runAfterLoad`
  三个函数 + 两处调用 + 两条破坏点一起删。
  → **判据：一条注册口子如果只剩"空转"，它就不是保障而是噪音。**
  同类问题：`G.ui.refresh()` **不含** `renderActions`（现在也不用含了）——
  **"某处状态换了、某块界面没跟着重画"是逻辑测试的盲区**，
  要专门读一遍"谁在什么时候重画"，而且**同一件事有几个调用点就要锁几条**
  （读档和导入就是两处，只验一条等于只锁一半）。

## 地图分层与素材组织

**三层：世界 → 区域 → 房间。**

| 层 | 是什么 | 放在哪 |
|---|---|---|
| 世界 | 全部内容 | 没有独立文件，就是所有区域加起来 |
| 区域 | 一组房间的归属，有一个「中心房间」 | `data/areas.js` |
| 房间 | 一块矩形格子地图 | `data/rooms/<区域 id>.js` |

- 区域字段：`id` / `name` / `center`（必填）、`parent`（可选，留给以后的子区域）。
- 房间字段：`id` / **`area`（必填）** / `name` / `desc` / `tiles` / `spawn` / `doors`。
- **一个区域一个文件。** 房间素材是 `data/rooms/<区域>.js`，文件里用
  `G.data.rooms.push( {...}, {...} )` 追加。房间多了不用全挤在一个文件里 ——
  长对话下改一个房间要读整份素材，很容易改错行。
- **加载顺序**：`js/data.js`（建空的 `G.data.areas` / `G.data.rooms`）
  必须排在 `data/areas.js` 和 `data/rooms/*.js` 前面。
- **新增区域文件后要在 `index.html` 补一行 `<script src>`**。开发环境和打包
  都照这份清单走，漏了就两边都漏（`build.mjs` 是照 `index.html` 内联的）。
  `validate.mjs` 反过来是扫目录的，新文件自动纳入校验。
- 当前只有 `hall`（大厅区域）一个区域，含大厅 + 四扇门通向的四间屋。

**为什么加这一层**：房间一多，光看 `doors` 的指向推不出"这屋属于哪一块"，
id 也容易撞车。有了区域，房间能按 `区域_房间` 命名，素材也能按区域分家。

**校验脚本解析素材的坑**（改 `validate.mjs` 时会撞上）：
- **两种写法配两个读函数，别混用**（用错会报一个莫名其妙的"找不到 `G.data.x = ...`"）：
  `G.data.x = [...]` 走 `loadTop()`（strings / areas / npcs / quests / events）；
  `G.data.x.push(...)` 走 `loadPushed()`（`rooms/*.js`、`skills.js`、`statuses.js`）。
  `loadPushed()` 返回**拍平后的数组**，多个文件就逐个读再拼。
- 找 `G.data.x =` 必须用正则要求"标记后面紧跟等号"。先找标记再找下一个等号，
  会被文件头注释里的等号骗到，报出来的错完全对不上真正的问题。
- `push(a, b, c)` 是**多个参数不是数组**，按 JSON 解析前要自己补一对方括号。
- 切 `push(...)` 的括号范围不能取最后一个 `)`，要扫一遍括号配平（注释里出现括号就会切歪）。
- **一个文件可以放好几块数据**（`data/npcs.js` 有三块）。切值不能"从 `=` 一直切到分号"，
  要扫配对括号只取那一对，否则把后面几块一起吞进来。切括号还要跳过字符串里的括号。
- **加一类新素材就补一段校验。** 第 19 轮新加了 `data/skills.js` / `data/statuses.js`，
  校验脚本当时**一段都没有** —— 新素材压根没被查。补上后能拦：id 前缀与唯一性、
  `mods.attr` 落在属性表里、`add`/`pct` 二选一、主动技能不许写 `mods`、
  `applies` 指向真实状态、`tick.key` 只允许 hp/ess 且只有 `unit==='step'` 配得上、
  `turns` 与 `unit` 要一致。**素材校验是"字段名漂移 / id 拼错 / 静默失效"唯一的机械闸门。**

## NPC / 任务 / 对话

**三块数据分家**：NPC 素材 `data/npcs.js`（类型表 / 态度阶段表 / NPC 本体，一个文件三块）、
任务定义 `data/quests.js`、任务进度 `js/quests.js`（`G.quests`）、对话 `js/talk.js`（`G.talk`）。

### NPC

- 类型表 `npcTypes`：`id` / `name` / `color`。**加类型只改这里** ——
  颜色由渲染写成格子上的 `--npc-color`，**地图上的字和那一格的边框用同一个色**。
- 态度阶段表 `attitudeStages`：`min` / `name` / `color`。
  **必须按 `min` 升序，第一项必须是 0**（映射是"取最后一个满足 `分数 >= min` 的"）。
  分数夹在 0–100。现阶段**只是展示**，没接任何玩法。
- NPC 表：`id` / `name` / **`glyph`（地图上画的那个字，跟名字分开定义）** / `type` /
  `attitude` / **`talk`（普通台词数组）** / **`at`（出现位置，数组）**。
- **`at` 是数组** —— 一个 NPC 能出现在多个房间、多个区域、同房间多处。
  是同一个 id、同一份态度和进度，不是复制成好几个。`npcsIn()` 会去重。
- **`talk` 是每个 NPC 自己的一组台词**，每次开口随机挑一句（走 `G.rng`）。
  任务对话不写在这里，那是任务自己的 `offer` / `turnin`。
- **NPC 挡路。** `walkable()` 把 NPC 算成障碍，玩家走不到它那一格上。
  配套三条：撞人的提示跟撞墙**分开说**（"某某挡在前面"）；能对话的只可能是**四邻**
  （`npcsNear()`）；**NPC 不能把路堵死** —— `validate.mjs` 从出生点做 BFS，每个门格必须走得到。
- **角标**：`G.quests.npcBusy(npc, room)` —— 有可接的、或者有能交的，就亮。
  用 `::after` 画，**不额外塞元素**（会破坏"一行 flex、格子定宽定高"的前提）。
  ⚠️ 可重复任务交付后立刻回"可接"，所以那个 NPC 的角标会**常亮**，见 99 的 H 组。

### 任务

- 任务字段：`id` / `name` / `desc` / `goal` / **`giver`（必填）** / `room`（可选） /
  `requires`（可选） / `repeatable`（可选） / `offer` / `turnin`。
- **任务与 NPC 不是绑定关系。** NPC 身上**没有**任务字段（旧的 `quest` 字段已废弃，
  `validate.mjs` 见到就报错）。任务自己声明 `giver` / `room`，`G.quests.ofNpc(npc, room)` 现算。
  好处：换人发布只改一行；同一个人在不同房间拿出不同任务只靠 `room` 一行。
- **三态**：`available`（可接）/ `active`（已接）/ `done`（已交付）。
  **「没有记录」= available**，所以旧存档零迁移。
- **「目标达成待交付」不单独占一个状态**，是 `active` 的派生（`isReady()`）。
- **未接收不可执行**：`add()` 只推 `active` 的任务。
- **任务链靠 `requires`**：前置没交付 → **完全不在 `ofNpc()` 里**（不是灰着、是根本看不见）。
- **可重复**：交付后 `state` 立刻回 `available`、`progress` 清零、`times` 累加。
- **进度不缓存在模块里**，每次现读现写 `G.state.data.quests`（`id -> { state, progress, times }`）。
  `normalize()` **故意不清理指向已删任务的记录**（任务下线再加回来，进度还在）。
- `add(type, n)` 返回**这一次刚达成目标的任务数组**（是"达成"不是"完成"）。
  进度**夹在目标值上**（不会停在 `12 / 10`）；只在**刚好跨过门槛**那一次报一次。

### 对话

- **`js/talk.js` 不碰 DOM，也不能反向调 `ui`**（`ui` 要读对话状态画面板，反着调就成环）。
  它只**产出事件列表** `{text, cls}`，调用方 `main.runTalk` 负责落日志与刷新。
- **对话是一排选项，一个任务就是一个选项。** 同一个 NPC 上普通对话 / 接任务 / 交任务并列。
- **台词随机挑一次就存住**，否则 `renderTile` 一刷新就重挑、台词疯闪。
- **对话状态不进存档**（瞬时状态）。
- **走开自动断**：`move()` 调 `drop()`，另外 `current()` 现算"人还在旁边吗"，双保险。
- `talk` 子命令：`chat` / `accept <id>` / `deliver <id>` / `bye` / `talk <npcId>`，
  面板按钮就是把子命令写进 `data-arg` 传回来的。

### 事件点

**跟 NPC 长得像，但是两回事。** 素材 `data/events.js`，执行 `js/events.js`（`G.events`）。

- **不挡路。** `walkable()` 只查 `npcIndex`，**永远不要**把事件点也加进去 ——
  玩家必须能走上去，这是整个功能的前提。跟 NPC 正好相反。
- **三个正交维度，不要写成一个类型枚举**（写成"泉水型 / 物品型 / 机关型"以后就没法加新组合）：

  | 维度 | 字段 | 取值 |
  |---|---|---|
  | 怎么触发 | 写了哪个回调 | `onCollide`（走上去自动）/ `onUse`（点按钮）/ 两个都写 |
  | 用完走不走 | `once` | `true` 用一次就没 / `false` 永远在 |
  | 藏不藏 | `hidden` | `true` 触发前只画空框 / `false` 一直画字 |

  类型表 `eventTypes` 给 `hidden` / `once` 的默认值，条目可覆盖。
- 字段：`id`（`ev_` 前缀）/ `type` / `name` / **`glyph`** / `at`（数组，同 NPC）/
  `desc` / `hint`（按钮上的字）/ `onCollide` / `onUse` / `once` / `hidden`。
  **两个回调至少要有一个**，都没有的事件点什么也做不了。
- **`at` 的约束跟 NPC 不一样**：不能墙里、**不能门格**、**不能出生点**、
  **不能开在 NPC 那一格上**（NPC 挡路，那一格永远走不上去）、同房间同格不重复。
  同一个 id 出现在多处 = 同一份状态（在一处用掉了，别处的也没了）。
- **效果**是一串小对象，键只允许 `log` / `cls` / `set`。
  `set` 的键是 `player.xxx` 点号路径，值是**带符号的字符串**（`"+1"` / `"-5"`），写数字会被校验拦下。
- ⚠️ **`G.rules.applyEffect` 是空壳，直接 `return false`，什么都不改。**
  玩法还没定（连有没有血量都没定），素材照写、照校验、照解析，就是不生效。
  等 A 组拍板**只改这一个函数**，素材一行都不用动。
  **别因为"反正没效果"就把解析或校验删掉** —— 删了以后加回来时，素材里写错的键就没人拦了。
- **状态**在 `G.state.data.events`：`id -> { times }`。**只记次数，不记布尔** ——
  一个 `times` 同时回答 `once` 的"用掉了没有"、`hidden` 的"揭开没有"、可重复的"踩过几回"。
  **"没有记录" = 一次都没触发过**，所以旧存档零迁移。存档 v3 → **v4**。
- **`G.events` 不碰 DOM**：`fire(ev, kind)` 只产出 `{ ok, events }`（`events` 是要写进记事的行）。
  **`ok` 只表示"这次有没有触发效果"，不是"玩家有没有到"** —— 这两件事混起来
  会让"走到泉水边"这种任务永远做不完。
- **任务目标**：`goal.type` 加 `reach`（走到）/ `use`（互动），**必须写 `goal.ev`**。
  推进走 `G.quests.reach(evId)`（直接置满）/ `use(evId)`（步进 1），**不走 `add()`** ——
  `add()` 只要知道"走了"，而"走到某个特定事件点上"必须知道是哪一个。
- **界面**：地图上 `#map .event`（实线框 + 类型色）；`hidden` 且没触发过 →
  `#map .event.hidden`（**虚线空框**，画一个**空格**而不是空字符串，
  这样每行文字长度还是跟列数一致）。**玩家优先** —— 站在事件点上时那一格画玩家自己的字。
  点位状态那一块叫「**地上**」（不叫"脚下"，"脚下"已经被"空地还是门"占用了），
  按钮**只在有 `onUse` 时画**（纯 `onCollide` 的动作是"走上去"，玩家已经走上来了）。
- `use` 指令：别名 `互动` / `用`，`quiet`，**不给 `btn`**（跟 `enter` / `talk` 一样绑在东西上）。
- 演示素材（都在大厅）：泉水 `(1,2)` / 地砖 `(2,2)` / 石龛 `(5,2)` / 铜钱 `(6,4)` ——
  四种组合各一个，石龛是唯一"两条触发路都通"的。

## 验证纪律

交付前必跑（详见 `docs/设定/08-技术约束.md`）：

```bash
node tools/validate.mjs
node tools/probe.mjs "file:///D:/魔鱼世界/index.html" tools/smoke.js
node tools/mutate.mjs          # 反向验证：故意改坏关键规则，确认冒烟拦得住（自动还原）
node tools/build.mjs
node tools/probe.mjs "file:///D:/魔鱼世界/dist/魔鱼世界.html" tools/smoke.js
PROBE_SIZE=1100,700 node tools/probe.mjs "file:///D:/魔鱼世界/dist/魔鱼世界.html" tools/smoke.js
```

- **逻辑对了不等于画对了。** 渲染是另一条代码路径，必须单独验。
- **布局也是单独验的。** 量真实外框（`getBoundingClientRect`），不是"元素存不存在"。
- 布局问题分宽度，换 `PROBE_SIZE` 再跑一遍。
- 无头验证前必须等 `document.readyState === 'complete'`，否则撞解析竞态。
- 不要用 `--virtual-time-budget` 配合 `setTimeout` 做超时兜底，虚拟时钟会提前触发，产生假阴性。
- 视口要显式锁（`Emulation.setDeviceMetricsOverride`），只给浏览器传 `--window-size` 在无头下不可靠。
- **不要靠 `focus` / `blur` 事件做逻辑判断**：无头浏览器里文档没焦点，Chrome 会推迟派发这两个事件。
- 测键盘要派发真的 `KeyboardEvent`，**同时给 `code` 和 `key`**（前者认方向键，后者认 `/` 和回车）。
- 测试自己也会写错。报失败时先怀疑测试，再怀疑代码。
- **冒烟里点按钮一律走 `clickArg` / `clickCmd` / `clickMove` 这几个包装，不要直接 `.click()`。**
  元素不存在时直接 `.click()` 会抛 `TypeError`，**整个脚本中途炸掉、后面的检查一条都不跑**，
  报出来的错还指不到真正的问题。包装函数找不到就返回 `false`，让断言变红就行。
- **反过来，`clickCmd` / `clickArg` 会真的点下去，不能当查询用。**
  `T('面板上有互动按钮', !!clickCmd('use'))` 会把一次互动提前消耗掉，
  后面一串断言跟着错（铜钱被提前抠走、石龛多触发一次）。
  断言"按钮在不在"用 `hasCmd(cmd)`（只看不点）。
- **断言里不要直接访问可能不存在的深层字段**（`G.state.data.events.ev_spring.times`）。
  上面某一步没走到时这里会抛 `TypeError`，同样会把后面几十条检查全带走。
  走 `G.events.times('ev_spring')` 这种有兜底的查询，或者先 `!!` 判一层。
- **断言要先把"前提"造出来，否则它在某些窗口尺寸下是恒真的。**
  验"选项多到装不下时滚到底能不能看全最后一个"时，宽窗口下面板有 390px、
  三个选项怎么都装得下 —— 这条在 1440×860 下永远绿，等于没写。
  改成**临时把面板压矮**（`style.maxHeight = '90px'`，量完还回去）把前提造出来。
- **前提要显式摆，别假设前面某一步已经把它摆好了。**
  验"进门不推进走路任务"时我以为 `q_walk20` 那时已经接了 —— 其实它只是"可接"，
  而没接的任务压根不推进，断言恒绿。先 `G.quests.accept()` 真的接下来
  （验完把记录整个还原）前提才算成立。
- **别拿 0.5px 的容差量"滚到底看不看得全"。** `scrollHeight` 是**取整**的：
  内容真实高度 193.5、`clientHeight` 190 时 `scrollTop` 最多到 3，
  最后那 0.5px 永远滚不出来 —— 那是取整残差，不是"被裁掉"。
  容差留到 2px，并且**量"露出来多少"**（可见区与按钮的重叠高度 ≥ 按钮高 − 2），
  不要量"按钮底边跟容器底边差几像素"。
- **断言的前提别挂在随机数上。** 台词是随机挑的，长短决定折 2 行还是 3 行，
  同一份代码连跑三遍能两红一绿 —— 典型的"前提没锁死"。
- **验"还原成功"要断言字面量，别拿变量跟它自己的副本比。**
  `const saved = obj.x; obj.x = 'x_nope'; ... obj.x = saved; T('还原了', obj.x === saved)`
  是**恒真**的，等于没验，还会掩盖"我记错了原值是什么"。要断言 `obj.x === '真实值'`。
  同一次还踩了另一半：那个"真实值"写成了**技能 id**，而 `applies` 里存的是**状态 id**
  （`skl_focus.applies === 'st_focus'`）—— **带 `skl_` / `st_` 前缀的字段要看清它该装哪一种。**
- **反向验证已脚本化**：`tools/mutate.mjs` 照一张"破坏清单"（现在 58 条）逐条改坏 → 跑冒烟 →
  数变红条数 → **立刻还原**。新加一组检查就往清单里补一条对应规则的破坏点。
  破坏点要挑**不会让冒烟中途抛错**的，否则看着"拦住了"其实什么也没验到。
  两个自坑：**别在 `to` 里引用那段代码自己正在定义的东西**（改 `rules.attrs` 时写过
  `G.rules.DIV_KEY`，那会儿 `G.rules` 还没赋上值，当场抛错）；
  **破坏点把冒烟自己搞崩时先修冒烟**（`G.statuses.find('x').left` 撞 null → 先存变量再判空）。
- ⚠ **`mutate.mjs` 要跑 3 分钟，别用会超时的前台命令跑**（第 21 轮踩的坑）。
  它靠 `finally` 还原，**被 SIGTERM kill 掉时 `finally` 根本不执行** ——
  那个正在改坏的文件就留在改坏状态了。症状很阴：冒烟里某条断言一直红，
  于是**每一条破坏点都"拦住了"**，整张清单的结果全被污染、看起来还全绿。
  现在脚本挂了 SIGINT / SIGTERM / SIGHUP 处理器先还原再退出，
  跳过的提示里也写明"可能是上次被中途杀掉"。**跑之前先确认工作区是干净的。**
- ⚠ **破坏点变红 ≠ 它锁的规则被拦住了。** 变红的可能是**别的**断言（见上一条）。
  **看结果要连"红了哪几条"一起看，不能只看"红了"。**
- ⚠ **断言量错了层级、或判据区分不出改坏前后，等于没写**（第 21 轮一次逮到两条**假阳性**）：
  1. 量 `#buffs` 的**按钮**宽度来验"不铺满整行" —— 把 `width: 100%` 加回按钮，
     一条断言都不红。因为按钮在"宽度由内容决定的 flex item"里，**百分比宽度是空操作**。
     要改成量 **`dd`（标签）**那一层，能拉满的只有它。
  2. 用"背包块变矮了"来验"背包吃剩余空间" —— 把 `1fr` 改成 `auto` 照样绿。
     因为 grid 的 `align-content: stretch` 默认**也会把 `auto` 行拉开**。
     换成"**状态面板里一点多余空白都没有**"（量 `#buffs` 底边 vs 面板内边距以内的底边，
     padding / border 用 `getComputedStyle` 取，改数值也不会失效）。
- **清单有两种判据，别混。** 默认是"改坏代码 → 数冒烟里 `✗` 的条数"；
  写了 `expect: '那句话'` 的是"**塞坏素材 → 看 validate 有没有报出来**"。
  **校验类规则只能用第二种**：把 validate 里某条检查删掉，结果是"校验通过了"，
  一个"通过"里数不出任何 `✗`，脚本会报"没有任何断言变红" —— 看着像拦住了其实什么也没验到。
- **拿不准就写探针量，别看截图猜。** 截图会被缩放、被相邻元素干扰，
  量 `getBoundingClientRect()` / `getComputedStyle(el, '::after')` 才是准的。
- **同一文件的多个 Edit 必须逐个来。** 一轮里发多个 Edit 到同一个文件，
  只有一条生效、其余被覆盖（踩过两次：`MEMORY.md`、`tools/validate.mjs`）。
  改完回读确认。

## 界面约定（P0 定稿）

**主界面骨架**（占满整个窗口，不留宽度上限）：

```
┌──────────────────────────────────────────────────────────────┐
│ 魔鱼世界   提示文字                          存档：未绑定      │
├──────────┬────────────────────────────────────┬──────────────┤
│ 玩家状态  │  地图              │ 地图点位状态    │  二级操作     │
│ 名字      │                    │  （一级区）     │              │
│ 生命 灵性 │                    │                ├──────────────┤
│ 属性 2 行 │                    │                │  操作区       │
│  3 列     │                    │                │              │
│ （带明细）│                    │                │              │
├──────────┤                    │                │              │
│ 状态      │                    │                │              │
│ [凝神][中毒] ← 标签并排，换行   │                │              │
│ （按内容高度）                 │                │              │
├──────────┤                    │                │              │
│ 玩家背包  ├────────────────────┴────────────────┤              │
│ （预留）  │  记事                                │              │
│ ← 吃余量  │                                     │              │
│          ├─────────────────────────────────────┤              │
│          │  > 输入行                    [发送]   │              │
└──────────┴─────────────────────────────────────┴──────────────┘
```

- 左栏 = 玩家自己的东西；中栏 = 地图与叙事（**一级**）；右栏 = 操作（**二级**）。
- **左栏只有三块：玩家状态 / 状态 / 玩家背包（预留）。没有「技能」块。**
  `#rail-left { grid-template-rows: minmax(0,auto) minmax(0,auto) minmax(0,1fr); }`
  玩家状态 / 状态按内容高度，**「玩家背包」吃剩余空间**（第 21 轮改回来的，第 20 轮曾是状态吃）。
- **「技能」块删掉的原因**：技能换了入口之后它就重复了 ——
  主动技能在「行动 → 释放法术」里，主动 + 被动总览在「其他 → 技艺」里，
  弹框比左栏那一小块宽得多、还能写描述。**被动技能没因此看不见。**
- **状态块按内容高度、并排成标签**（`#buffs` 是 `flex-wrap`）：
  每个状态只占自己文字那么宽，一行放不下自动换行。
  一个状态占满一整行太浪费 —— 左栏本来就窄，状态名通常两三个字。
  **它不再需要靠拉伸来容纳**（余量才给回背包的）。
- **左栏的下限比右栏大**（250px vs 180px），因为属性明细是 **3 列并排**，
  每列要装下「(5+1+0+0)」这样一行（11 个字符）。**这一条是量出来的，不是估的**：
  1100×700 下左栏 190px 时每格 52px、文字 58.1px，正好横向溢出格子。
- **右栏上 = 二级操作、下 = 操作区**（曾经是反的，也曾经叫「预留区域」）。
  二级操作的内容会随情况变长（对话选项一多就长），所以让它吃剩余空间、内部滚动；
  操作区是固定的那几组通用指令，按内容高度就好。
  `#rail-right { grid-template-rows: minmax(0, 1fr) minmax(0, auto); }`
  —— 用 `minmax(0, auto)` 而不是 `auto`：窗口太矮时操作区能被压下去内部滚动，
  而不是把整条右栏顶出去。
- **记事横跨"地图 + 地图点位状态"两块宽度**；**输入行只在中栏底下，不占满全宽**。
- 左右两栏各自上下分块。以后加背包/装备/小地图都有位置，不用再动骨架。
- 左右两栏用 `clamp()` 限宽（跟着窗口走但有上下限），中栏吃剩余宽度。
- **两块屏**：创建角色是独立整页（不走指令），游戏主界面是另一屏。无存档时只显示创建页。
- **操作区按用途分组**：移动 / 行动 / 存档 / 其他。`reset` 不给按钮，只能打字，防手滑。
  **四组现在都是静态的** —— 指令表变了操作区才变，跟角色无关。
- **「技能」组已废弃（第 20 轮）。** 它原来是按"拥有几个主动技能"现生成的动态组，
  是**唯一不从 `CMDS` 静态表来的分组**，所以到处都要补 `G.ui.renderActions(actionGroups())`
  （踩过：只在 `init()` 里跑一次，那时 `G.state` 还是空的、技能组根本没渲染出来，
  冒烟里点技能按钮直接抛 TypeError）。现在改成：
  **操作区一个固定的「释放法术」按钮**（`cast`，**不带 `arg`**）→ 点开弹框列法术 →
  释放某一个走弹框里的按钮（`data-cmd="cast" data-arg="<技能 id>"`）。
  换来的好处是**操作区内容跟角色彻底解耦**：读档 / 导入换个角色，按钮一个字节都不变。
  **主动技能对外叫「法术」，主动 + 被动一起叫「技艺」**（`kind` 仍是 `active`、指令仍是 `cast`）。
- **动作属于哪个东西，按钮就跟着那个东西出现。** 不要什么都往操作区里堆。

  | 东西 | 什么时候出现 | 在哪一层 | 出现什么 |
  |---|---|---|---|
  | 门 | 站在门格上 | 一级（中栏点位状态） | 「进入这扇门」按钮 |
  | 事件点 | 站在它上面且写了 `onUse` | 一级（中栏点位状态） | 一块「地上」+ 互动按钮 |
  | 人 | 站在人旁边 | 一级（中栏点位状态） | 「跟某某说话」按钮 |
  | 对话 | 已经开口了 | 二级（右栏二级操作） | 一排选项：随便聊聊 / 接受任务 / 交付任务 / 结束对话 |
  | 状态 | 身上挂着 | 一级（左栏状态块） | 状态名本身就是按钮，点开看详情 |

  条件不成立时那些按钮**根本不存在**，也就点不出"条件不成立的动作"。
  `enter` / `talk` / `use` / `buff` 因此都不在操作区里 ——
  `cast` 是例外（不带参数时是"打开列表"，不需要对象也能用）。
- **存档绑定状态放顶栏右侧**，不放玩家状态里 —— 它属于整个程序，不属于角色。
- **一级区（中栏「地图点位状态」）只讲"脚下这一格 + 旁边有谁"**：
  区域 / 房间 / 坐标 / 脚下是空地还是门 / 这扇门通往哪里，
  站在门格上时多一个「进入这扇门」按钮，站着人时多一块「旁边的人」。
  **不列四邻可走方向、不统计本室出口** ——
  前者跟地图重复（走得通的格子地图上本来就能点、悬停会亮），后者是开发信息、
  还跟「通往」容易看串。这两项连计算一起删了，不只是不显示。
- **「旁边的人」永远列着四邻的所有人**（不只正在说话那个）：
  人名 / 类型 · 态度阶段 分数 / 「跟某某说话」按钮。
  叫「旁边的人」不叫「脚下的人」—— NPC 挡路之后人只可能在四邻。
  **正在说话的那个按钮加 `.cur` 高亮**，点另一个人的按钮**直接切过去**，
  不用先按「结束对话」。（以前开口后整块被对话面板顶掉，第二个人就"消失"了。）
  **这里不报任务进度**（进度只在二级区看）；能接 / 能交的任务也不在这里列。
- **二级区（右栏「二级操作」）放"点开之后能做什么"**：
  抬头（正在跟谁说话，带 NPC 类型色）+ 台词 + 任务进度 + 选项按钮。
  空闲时是一句灰提示（`#secondary.idle`，居中）。
  **名字和态度不在这里重复画** —— 一级区那两行就是给这个用的，
  而且当前说话的人在一级区是高亮的。两块面板各讲自己那一层，不互相抄。
- **选项全塞进同一个 `dd.acts`**（flex 列 + 6px gap）。
  这么排是因为面板窄：一个选项占一个 `dd` 的话，选项一多就把面板撑出滚动条、
  最下面那个按钮被裁掉。面板本来就有 `overflow-y: auto`，小窗口下滚动是设计内的 ——
  测试断言验的是"**滚到底就能完整看到最后一个选项**"，不是"永远不滚动"。
- **CSS 共用选择器要写 `:is()`。**
  `#tile, #secondary dd.act button` 是**两条**选择器（裸 `#tile` + `#secondary dd.act button`），
  不是"两块面板"。要"两块面板"就写 `:is(#tile, #secondary) dd.act button`。
  批量替换字符串会把复合选择器改坏 —— 踩过一次（`#tile` 里的按钮一条样式都没上）。
- **删功能要连计算一起删。** 界面上藏起来但每帧还在算，等于留了个没人看的坑。
  测试里补"不再出现"的反向断言，防止哪天又被人加回来。

**弹框（模态浮层）** —— 第 20 轮加的，项目里第一次出现浮层：

- **归 `ui` 管，是纯外观状态。** `G.ui.openModal(kind, arg)` / `closeModal()` / `modalOpen()`。
  `kind` 现在三种：`spells`（法术列表）/ `arts`（技艺总览）/ `buff`（某个状态的详情）。
- **键盘归属仍然归 `main`** —— `main.onKey()` 第一句就是
  `if (G.ui.modalOpen()) { …Esc 关掉…; return; }`。
  弹框开着时方向键 / WASD / `/` 一概不生效（否则玩家关掉弹框会发现角色走远了）。
- **弹框里的按钮照样是 `button[data-cmd]`**，走 `main` 的全局点击委托，不另开一套。
  唯一的例外是 `data-modal="close"`（关闭按钮和遮罩），也走同一个委托。
- **遮罩 `#modal-mask` 和方框 `#modal-box` 是兄弟不是父子** ——
  所以"点方框里面不关、点遮罩才关"不用在 JS 里判断（冒泡到不了遮罩）。
  **别改成父子**，否则要在 `#modal-box` 上 `stopPropagation()`。
- **`openModal()` 里先 `el.modal.hidden = false` 再 `renderModal()`** ——
  `renderModal()` 有"开着才画"的闸，顺序反了会先画一次空内容。
- 三种关法：`Esc` / 关闭按钮 / 点遮罩。`refresh()` 末尾会调 `renderModal()`，
  所以弹框开着时底下的数据变了（比如状态剩余量），弹框里的数字是活的。
- **状态详情四块固定：描述 / 剩余量 / 影响 / 计时**（第 20 轮拍板）。
  描述为空就**整块不画**；影响为空要明说「不改变任何属性。」；
  剩余量跟着 `unit` 变说法（`step` → "还能走 N 格" / `time` → "还能持续 N 秒" /
  `manual` → "不会自己消失" / `threshold` → "不由计时决定，去留看条件"）。

**地图画法**（正方形格子）：

- 字符约定：`#` 墙、**门格画一个「门」字**、**NPC 格画它的 `glyph`**，**空地不画任何字符**。
  **只换字形不换定义**：门在素材里是 `rooms[].doors` 的一条（键 `"x,y"`），
  `tiles` 里根本没有 `+`，判定一律走 `G.data.doorAt()`。字形收在 `js/ui.js` 的 `DOOR_GLYPH`。
  门字是满宽汉字，单独缩到格子的 0.7；橙色底块照旧铺满整格。
- **NPC 画的是 `glyph` 不是 `name`**（名字两三个字，格子放不下），颜色取自类型，同样缩到 0.7。
  **外面套一圈类型色的细框** —— 跟玩家绿框同一个做法（`inset` 阴影，不占布局），
  颜色走同一个 `--npc-color`，改类型表就换色。
- **玩家和 NPC 不可能同格**（NPC 挡路）。撞人时说「某某挡在前面，过不去」，
  跟撞墙的「那边是墙」分开 —— 都说"墙"会让玩家以为地图画错了。
- **玩家那一格画角色名的第一个字**（`Array.from(name)[0]`，不用 `charAt(0)`——表情符号占两个码元会被切坏），
  外面套一圈绿框 + 淡底色。不用 `@`：地图上东西一多，`@` 跟别的符号撞脸，玩家分不出哪个是自己。
  玩家格缩到 0.62。
- **墙不画 `#` 字形**，用背景色铺满整格，相邻墙格连成一片。
- 格子边长 `--cell`、字号 `--fs` 都由 `js/ui.js` 按面板大小算：
  `min(可用宽÷列数, 可用高÷行数)` 夹在 16–56px。小图放大填满，大图缩到看得清。
- 量可用空间用 `clientWidth / clientHeight`，**不用 `getBoundingClientRect()`**（后者不扣滚动条）。
- 字号直接跟格子边长挂钩（`min(cell×1.0, cell×0.86÷字宽比)`），
  **不要按"字宽"反推**——那样字体的高度会把格子纵向撑爆，地图上会多出滚动条。
- 每行 `display:flex`，格子是定宽定高块，内部再用 flex 居中。**不要用行内块 + 行高**。

**方向词一律上下左右**，不用东西南北。网页是二维的，玩家看到的就是上下左右。
门名同此（"上面的铁门"）。

## 玩家状态与数值（第 19 轮定稿，第 20 轮补面板明细）

**玩家没有等级、没有经验、没有金币。** 成长只走两条路：技能（拥有即生效）+ 状态（挂着会过期）。

属性只有一条链路，公式写在 `js/rules.js`，**数值写在 `data/`**：

```
固有[attr] = (基础 + Σ被动加值) × (1 + Σ被动百分比 ÷ 100)
惩罚系数    = 生命 ≤30% → 0.6 ；≤60% → 0.8 ；否则 1     （按 当前值÷当前上限 判）
最终[attr] = (固有 × 惩罚系数 + Σ状态加值) × (1 + Σ状态百分比 ÷ 100)   再四舍五入
```

三条不能改的：

1. **取最严重的一档，不叠加**（生命 25% 只按 ×0.6，不是 ×0.6×0.8）。
2. **惩罚只削"角色固有"那一段**（基础属性 + 被动技能）；
   **主动技能和状态施加在惩罚之后，不吃削减**。
3. **惩罚是派生值，不写回 `base`。** 力量 10 掉到 8，生命回到 60% 以上自动变回 10。

**面板上的属性拆解（第 20 轮）** —— 括号里显示 `(基础+被动+状态+装备)` 四段。

用户原本要的是五项（基础 / 主动 / 被动 / 状态 / 装备），拍板**合并成 4 项**：
**主动技能本来就统一挂状态生效，没有独立的"主动值"**，它的贡献算进「状态」。

式子对每一项都是**乘法（线性）**的，所以能精确拆出**惩罚后的实际贡献**
（拍板要"惩罚后"，这样四项相加 ≈ 总值，玩家能自己核对）：

```
基础贡献 = 基础值     × 被动因子 × 惩罚 × 状态因子
被动贡献 = Σ被动加值  × 被动因子 × 惩罚 × 状态因子
状态贡献 = Σ状态加值  × 状态因子          ← 状态不吃惩罚，少两个因子
装备贡献 = 0                              ← 装备系统还没做，恒为 0
四项相加 = 总值（差个四舍五入）
```

- 实现在 `G.rules.attrParts()`（`js/rules.js`）。
  **`total` 走跟 `finalAttrs()` 同一个表达式，不是把四段加起来** ——
  避免浮点结合律差出 1 点。
- 四项配色固定，**全部取自主题变量，代码里不许写死色值**：
  基础 `--fg-dim`（灰）/ 被动 `--accent`（绿）/ 状态 `--info`（蓝）/
  装备 `--gear`（紫，第 20 轮新开 —— 原来那套语义色里挑不出合适的）。
- **受惩罚时标的是"每一格的总值"（`--warn`），六格全标**，括号明细不变色。
- 布局是 **2 行 3 列**（不是 6×1），把省下来的纵向空间让给下面的「状态」块。

其他关键约定：

- **六项基础属性**（`str`/`int`/`spr`/`dex`/`luk`/`per`）初始都是 5；
  **神性 `div` 不在 `attrs` 表里** —— 参与判定但不上面板，基础 0。
- **生命 / 灵性是百分比**（`hp`/`hpMax`、`ess`/`essMax`，0–100），初始满值，
  面板显示百分比 + 一条细进度条。
- **灵性不走属性惩罚，改走状态触发**：≤20% → `st_drained`（灵性枯竭），
  0% → 换成 `st_exhausted`（灵性耗尽），两个效果暂空。
- **主动技能统一走"挂状态"生效**（`applies` 指向一个状态）——
  所以公式里只有"状态"一项修正，不分"技能修正"和"状态修正"。
- **最终属性不存进存档**，每次现算 → 杜绝"改了技能忘了同步属性"的不一致。
- **状态是唯一能自动改生命 / 灵性的东西**（`tick`）——
  `G.rules.applyEffect` **仍然是空壳**，因为"扣到 0 之后怎么办"没定，不能替玩家拍板。
- **状态的四个正交维度**（跟事件点一个思路，"写了哪个字段就有什么行为"）：
  正负面看 `kind`（**只影响配色**）/ 改不改属性看有没有 `mods` /
  会不会掉血看有没有 `tick` / 会不会过期看 `unit`。
  **不要写成"中毒型 / 祝福型"的枚举。**
- `unit` 里 **`'time'`（按真实秒数计时）的计时器还没实现** ——
  `tickStep()` 只认 `'step'`。`tools/validate.mjs` **直接拦下**这种素材，
  免得埋一个从界面上完全看不出原因的坑。
- **存档 v5**：v1–v4 一律抛错拒绝（player 结构整个换过），**不做迁移，回到创建页重开**。

## 操作方式（P0 定稿）

**四条路走同一张指令表**（`js/main.js` 的 `CMDS`）：键盘 / 操作区方向盘 / 点地图相邻格子 / 指令输入。

**走路模式 / 命令模式**——这是核心设计，别改回去：

- 走路模式（默认）：键盘归游戏。`↑↓←→`、`WASD`、小键盘 `8 2 4 6` 直接走，不用回车。
- 命令模式：键盘归输入框。按 `/` 或回车进，`Esc` 或执行完指令自动回。
- 为什么必须分：走路用 `w a s d`，而存档是 `save`、向下是 `s`，同一个键不可能既是走又是打字。
- **模式只是外观**。按键归谁管看 `document.activeElement`，不看 class。
- 指令打错时留在命令模式；空回车 = 退出。

其他约定：

- **按 `e.code` 认键，不按 `e.key`** —— 中文输入法下 `e.key` 会变，`e.code` 永远是物理键位。
- **进门键**：小键盘 `5` / `.` / 空格。
- **按住连走要节流**（`REPEAT_MS = 110`），不然日志被刷屏。
- **移动类指令标 `quiet`，不回显**。手打的仍回显（玩家得看见自己打了什么）。
- **执行完指令要摘掉焦点**。以前每次都把光标塞回输入框，方向键全被吃掉。
- **移动组的按钮排成方向盘**（`PAD_GROUPS`），不排成一行。
