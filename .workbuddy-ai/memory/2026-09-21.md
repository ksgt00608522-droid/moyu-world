### 技术栈提案（待用户确认）
- 语言：原生 ES Module JavaScript，**零构建步骤**；用 `// @ts-check` + JSDoc 拿编辑器类型提示。TS 仅在逻辑超 ~3000 行后再考虑。
- 渲染：DOM（非 Canvas），三区布局 = 叙事日志 + 状态面板 + 指令输入行。
- 样式：手写 CSS + CSS 变量主题；中文用系统等宽栈，不用像素字体（CJK 字库过大）。
- 逻辑：纯函数 + 单一 state 对象；命令解析用动词表 dispatch；战斗为回合制状态机，逻辑产出事件列表、UI 只负责播放。
- 随机：自实现 mulberry32 种子 PRNG，seed 存档 → 出 bug 可 100% 复现。
- 数据：`data/*.json`（monsters / maps / items / skills / strings），ID 引用不内联对象。
- 开发期加 `tools/validate.mjs`（纯 Node 无依赖）校验 AI 生成的 JSON，防字段漂移。

### 存档分层（核心方案）
- L1 IndexedDB 自动存档（日常无感）
- L2 **File System Access API 绑定真实磁盘 .json 文件**（清缓存不丢，解决痛点）
- L3 手动导出 / 导入 JSON（兜底 + 跨设备）
- L4 base64 存档码（可选）
- 备选兜底：20 行本地小服务 `POST/GET /save` 直接读写文件（最稳，但多一个进程）
- 存档文件放项目目录并纳入 git，等于免费的时间机器

### 明确不做
后端/账号/云同步；npm 依赖树；Canvas/WebGL/游戏引擎；PWA 离线缓存（前期）。

### 补充结论：不需要 Python
静态服务器只是"给浏览器一个 http origin"，跟 Python 无关。由于要加存档落盘接口，
最佳方案是项目自带 `serve.mjs`（Node 内置模块，零依赖，约 22 行）：
同时提供静态文件服务 + `GET/POST /save` 存档读写。本机 Node 22/24 均可用。
- 明确：file:// 下 ES Module 会被 CORS 拦（origin 为 null），fetch 本地 JSON 也会被拦，
  所以只要分文件写代码就必然需要一个 http 服务器——这是浏览器安全模型，不是 Python 的问题。
- 唯一能彻底不要服务器的路径：把 JS 和 JSON 全部内联进单个 .html（可作为后期"打包产物"）。

## 追加需求：交付形态 = 压缩包，对方双击 HTML 即玩，零环境

### 实测结论（无头 Edge / Chromium + CDP，`file://` 协议）
探针脚本：`C:\Users\L1860\AppData\Local\Temp\rpgprobe\cdp-probe.mjs`
（用法：`node cdp-probe.mjs <file:// URL> [表达式文件]`，零依赖，靠 Node 22 内置 WebSocket + CDP）

| 能力 | file:// 实测结果 |
|---|---|
| 普通 `<script src="js/x.js">` | ✅ 可用 |
| ES Module（import / type=module 加载外部文件） | ❌ Failed to fetch（CORS，origin 被当作 null） |
| `fetch('./data.json')` | ❌ TypeError |
| localStorage / sessionStorage | ✅ 可用 |
| IndexedDB（open + 事务写） | ✅ 可用 |
| `showSaveFilePicker` / `showOpenFilePicker` | ✅ 存在且通过安全上下文检查（只报 "Must be handling a user gesture"） |
| Blob + `<a download>` | ✅ 可用 |
| `isSecureContext` | true；`location.origin` = `file://` |

⚠️ 踩坑记录：第一次测 IndexedDB 报 timeout 是**假象**——`--virtual-time-budget` 会把 `setTimeout` 提前触发。
凡是用定时器做超时兜底的无头测试，在虚拟时钟下都不可信，必须走 CDP `Runtime.evaluate` + `awaitPromise`。

### 架构转向（重要）
1. **放弃 ES Module**，改用普通 `<script src>` + 全局命名空间 `G`（IIFE 挂载）。多文件版本也能直接双击运行。
2. **数据文件从 `.json` 改为 `.js`**：`data/monsters.js` 内容为 `G.data.monsters = [ ...纯 JSON 字面量... ];`
   → 仍可用 `JSON.parse`（剥掉前缀）做 schema 校验，validate.mjs 不受影响。
3. **开发环境 = 交付环境 = file://**，避免"开发时好好的、发出去就炸"。
4. **删掉 serve.mjs**——file:// 全通了，本地服务器不再需要。零服务器、零构建工具、零依赖。

### 交付管线
- 开发期：多文件，双击 `index.html` 即跑
- 交付期：`node tools/build.mjs`（零依赖，约 60 行，纯字符串内联）→ 产出单个 `魔鱼世界.html`
- 单文件优于多文件：不用解压；从 zip 里直接双击会解到临时目录且路径每次不同；不会漏发文件导致白屏

### 存档（针对"给别人玩"重排）
- L1 localStorage 自动（file:// 可用；注意**所有本地网页共享同一 localStorage**，key 必须加命名空间）

### 地图正方形格子的实现（踩了两个坑）
1. **坑一：`letterSpacing` 补足法让墙变虚线。**
   一开始用 `letterSpacing = cell - advance` 把字符盒撑成方形，但 `#` 字形比格子窄，
   墙看起来是断续的虚线。改成 `display:inline-block` + 宽高都等于 `--cell`，墙用背景色填满整格。
2. **坑二：换行符把行距撑大了。**
   用 `\n` 分行时，换行符高度跟父级 `line-height`（1.65 × 22px ≈ 36px）走，格子只有 19px，
   行与行之间出现大空隙，地图被拉成长方形。改成一行一个 `<div class="row">`，行高固定为 `--cell`。
   → 冒烟测试正是靠"行间距等于格子高"这一条抓出来的。
3. 地图再套一层 `.grid`，用 `margin:auto` 在面板里居中——不用 `justify-content`，
   因为内容超出容器时 `justify-content` 会把上边裁掉，`margin:auto` 会正常出滚动条。

## 第七轮：移动操作方式重做 + 键盘控制

### 用户要求
「现在移动有不方便，想想有没有办法改一下移动的操作方式，并追加键盘控制。」

原来的痛点：走一步要么点右栏按钮、要么在输入框打字+回车；而且每次执行完指令
`G.ui.focus()` 都把焦点塞回输入框，方向键按下去只在框里移光标。

### 最终方案：四条路走同一张指令表

| 路子 | 触发方式 |
|---|---|
| 键盘 | 方向键 / WASD / 小键盘 8 2 4 6 |
| 操作区 | 方向盘按钮 |
| 地图 | 点玩家相邻的格子 |
| 指令输入 | `/` 或回车 → 打字 → 回车 |

### 走路模式 / 命令模式（核心设计）
键盘只有一个：走路用 `w a s d`，而存档是 `save`、向下是 `s`，同一个键不可能
既是"走"又是"打字"。与其猜，不如分两个模式，切换只要一个键：

- **走路模式（默认）**：键盘归游戏。输入栏边框暗、提示语是「↑↓←→ / WASD 走路　按 / 输入指令」。
- **命令模式**：键盘归输入框。按 `/` 或回车进，`Esc` 或执行完指令自动回。
- 指令打错时**留在命令模式**方便接着改；空回车 = 退出。
- **模式只是外观**：按键归谁管看的是 `document.activeElement`，不是那个 class。

## 第九轮：玩家标记改成角色名首字

### 用户的话
「人物不要用"@"符号了，看看能不能用角色的姓名第一个字加个边框，
好看一点避免出现和其他东西同名的时，玩家分辨不了」

### 为什么改
`@` 是个通用符号，地图上以后会有怪物、NPC、道具，`@` 跟别的字符容易撞脸。
名字首字是**这个人独有的**，再套一圈框，一眼就能认出哪个是自己。

### 怎么做的

`js/ui.js` 新增 `firstChar()`：

```js
/* 取名字的第一个字当玩家标记。
   用 Array.from 而不是 charAt(0)：表情符号这类字符占两个 UTF-16 码元，
   charAt 会把它切成半个乱码方块。 */
function firstChar(s) {
  var t = String(s == null ? '' : s).trim();
  if (!t) return '?';
  return Array.from(t)[0];
}
```

`renderMap()` 里取玩家首字，替换掉原来写死的 `'@'`：

```js
var me = G.state.player();
var meCh = firstChar(me && me.name);
/* 循环内 */
if (px === x && py === y) { ch = meCh; cls = 'me'; }
```

`css/theme.css` 的 `#map .me`：

```css
#map .me {
  color: var(--accent);
  background: rgba(94, 227, 154, 0.14);
  box-shadow: inset 0 0 0 2px var(--accent);   /* 框用 inset 阴影画，不占布局 */
  border-radius: 3px;
  /* 汉字是满宽的，照 --fs 那么大会顶到框上，缩一点留出边距 */
  font-size: calc(var(--cell, 18px) * 0.62);
  font-weight: 700;
}
```

### 两个要注意的点
- **框不能用 `border`**。`border` 会把格子撑大两像素，七行叠起来就顶出滚动条 ——
  这正是前几轮踩过的坑。用 `box-shadow: inset` 画框，画在格子里，不参与布局计算。
- **字号要单独覆盖**。`--fs` 是给地图上所有格子算的统一字号，玩家格是汉字，
  满宽的字照 `--fs` 那么大正好顶到框上，所以按格子边长重新算一个（×0.62）。

## 第十轮：门在地图上画成「门」字

### 用户的话
「现在地图上门的样式能不能改为写着一个门字，但本体还是用+号」

### 先把「本体」查清楚
用户说「本体还是用 + 号」，我先去翻了素材，发现一件事：

**`data/rooms.js` 的 `tiles` 里根本没有 `+` 这个字符**，只有 `#` 和 `.`。
门是单独写在 `rooms[].doors` 里的一条，键是 `"x,y"`。`+` 从头到尾只是
`renderMap()` 在渲染时临时画上去的一个字形。

所以「本体」根本不需要动 —— 门在数据层的定义（`doors` 条目 + `G.data.doorAt()` 判定）
跟画什么字毫无关系。这次改的纯粹是渲染层的字形。

### 怎么做的

`js/ui.js` 模块级加一个常量，把字形收在一处：

```js
/* 门在地图上画出来的字形。只是"画什么字"，不是门的定义 ——
   门在素材里是 rooms[].doors 里的一条，判定一律走 G.data.doorAt()，
   跟这个字长什么样没关系。以后想换个字（或者换成图标）改这一处就够。 */
var DOOR_GLYPH = '门';
```

`renderMap()` 里那一行：

```js
} else if (G.data.doorAt(room, x, y)) {
  ch = DOOR_GLYPH; cls = 'door';     /* 原来是 ch = '+' */
}
```

`css/theme.css` 的 `#map .door` 加字号覆盖：

```css
#map .door {
  color: var(--door);
  background: rgba(255, 180, 84, 0.16);   /* 橙色底块照旧铺满整格 */
  font-size: calc(var(--cell, 18px) * 0.7);
  font-weight: 700;
}
```

### 一个要注意的点
**「门」是满宽汉字，不能照 `--fs` 画。** `--fs` 是按等宽字形算的，
汉字宽度 = 字号，照 `--fs` 那么大会正好贴到格子边上。
所以门格单独缩到格子的 0.7（玩家格是 0.62 —— 玩家格有 2px 的框要留边距，门格没有）。

### 踩到的三个坑（都跟校验脚本解析素材有关）

1. **`extract()` 被注释里的等号骗了。** 原来的写法是"找到标记、再找下一个等号"，

3. **切 `push(...)` 的括号范围不能取最后一个 `)`。** 注释里出现一个括号就切歪。
   改成扫一遍括号配平，顺便跳过字符串里的括号。

三个坑的共同点：**解析源码的脚本，最容易被源码里的注释和字符串骗到。**

# 第 14 轮 · 任务接取制 + 对话系统 + NPC 挡路

用户一次提了 7 条：任务要先接收才能做 / 线性任务链 / 任务与 NPC 非绑定 /
可重复任务 / NPC 要有边框 / NPC 不可通行 / 任务通过对话接收且每个 NPC 有独立普通对话。

用 AskUserQuestion 问出 4 个设计决定：
- 接交粒度 → **对话是一排选项，一个任务就是一个选项**（普通对话 / 接任务 / 交任务并列）
- 可重复任务 → 交完**回到可接 + 记完成次数**
- NPC 边框 → **类型色细框**
- 普通对话 → **一组台词，每次随机挑一句**

## 做了什么

### 任务三态（`js/quests.js` 整个重写）
- `available` / `active` / `done`。**「没有记录」= available**（旧存档零迁移）。
- **「目标达成待交付」不单独占一个状态**，是 active 的派生（`isReady()`）。
  少一个状态少一处不同步。
- **未接收不可执行**：`add()` 只推 `active` 的任务。
- **任务链靠 `requires`**：前置没交付 → **完全不在 `ofNpc()` 里**（不是灰着）。
- **可重复**：交付后 state 立刻回 `available`、progress 清零、`times` 累加。
- 删掉了 `npcDone`，换成 `npcBusy(npc, room)`（问"还有没有活给你"）。

### 任务与 NPC 非绑定
- 删掉 NPC 的 `quest` 字段。任务自己声明 `giver` / `room`，`ofNpc(npc, room)` 现算。
- 好处：换人发布只改一行；同一个人在不同房间拿出不同任务只靠 `room` 一行
  （商人「搭把手」写 `room: room_right`，站在大厅时不拿出来）。

### 对话（`js/talk.js` 新建）
- **不碰 DOM**，只产出事件列表 `{text, cls}`，调用方 `main.runTalk` 负责落日志与刷新。
  原因：`ui` 要读对话状态画面板（ui → talk），反着调就成环。
- **台词随机挑一次就存住**，否则 `renderTile` 一刷新就重挑、台词疯闪。
- **对话状态不进存档**（瞬时状态）。
- **走开自动断**：`move()` 调 `drop()`，另外 `current()` 现算双保险。
- `talk` 子命令：`chat` / `accept <id>` / `deliver <id>` / `bye` / `talk <npcId>`。

### NPC 挡路 + 类型色边框
- `walkable()` 把 NPC 算成障碍；第 4 参数透传索引，避免渲染地图时白建四次。
- **撞人说"某某挡在前面"，跟撞墙分开说** —— 都说"墙"会让玩家以为地图画错了。
- 边框 = 类型色 `inset` 阴影（跟玩家绿框一个做法，不占布局）。
- 能对话的只可能是四邻 → 面板那块从「脚下的人」改名「**旁边的人**」。

### 校验脚本
- 任务新字段校验（giver 必填、requires 不能自指/成环、repeatable 必须布尔）
- **交叉检查**：giver 存在、room 存在、**giver 必须真的会出现在 room 里**
- NPC：`talk` 必须是非空字符串数组；**见到 `quest` 字段直接报错**（已废弃）
- **NPC 不能把路堵死**：从出生点按"NPC 挡路"规则做 BFS，每个门格都必须走得到

## 踩的坑（重要）

### 冒烟脚本点按钮找不到元素时会抛错，整轮作废

# 第 15 轮 · 事件点

## 需求（用户原话）

> 现在开始添加事件点功能，事件点不是NPC，触发后有可能消失，也有可能还在。人物可以走上事件点。
> 比如：泉水事件点：互动可以和水，互动后不消失。
> 物品事件点：互动可以捡起，互动后消失。
> 触发事件点：走到就自动触发，不显示文字只显示边框，触发可能出现多种事件，走到前无法察觉，
> 有可能是互动后不消失的触发事件点，触发后可以看到了。

## 两轮追问定下的 6 条

1. 触发型走上去之前怎么画 → **一直画空框**（只有边框、没有字）
2. "触发可能出现多种事件" → **提前编辑好的指定事件**（写死在素材里，不随机抽）
3. 触发后不消失的，再次走上去 → **每次都再触发**
4. 效果范围 → **记事 + 去留 + 数值**
5. 扣到 0 怎么办 → **先不用真扣**（"说不定后面我没有扣血事件也没有血量呢"）
6. 要不要接进任务系统 → **`reach`（走到）+ `use`（互动）两种都加**

## 核心设计：三个正交维度

**没有写"泉水型 / 物品型 / 机关型"这种枚举**，而是拆成三个互不相干的维度：

| 维度 | 字段 | 取值 |
|---|---|---|
| 怎么触发 | 写了哪个回调 | `onCollide`（走上去自动）/ `onUse`（点按钮）/ 两个都写 |
| 用完走不走 | `once` | `true` 用一次就没 / `false` 永远在 |
| 藏不藏 | `hidden` | `true` 触发前只画空框 / `false` 一直画字 |

三个随便组合都合法，以后加"踩了会响、还能再点一下"这种组合**不用改代码**。
类型表（`eventTypes`）给 `hidden` / `once` 的默认值，条目可以覆盖。

**事件点不是 NPC**，最本质的差别是**不挡路**：`walkable()` 只查 `npcIndex`，
永远不要把 `eventIndex` 加进去。

## 踩的坑

### 1. 并行编辑同一个文件，后者把前者覆盖掉

一条消息里发两个 Edit 改同一个文件时，两个都基于**原始内容**算新内容再写回，

以及 `Cannot read properties of undefined (reading 'times')`。

**教训：同一个文件的多处改动要分成多条消息，或者用一次 Edit 覆盖整段。**

### 2. `clickCmd` 被当成查询用

`clickCmd('use')` 会**真的点下去**。我把它写在
`T('面板上有互动按钮', !!clickCmd('use'))` 里当存在性断言，
结果铜钱被提前抠走、石龛多触发一次，后面一串断言跟着错。

补了一个 `hasCmd(cmd)`（只看不点），断言"按钮在不在"一律用它。

### 3. 玩家站在事件点上时，那一格画的是玩家

所以"事件点没了之后那一格变回空地"这类断言，**必须等走开之后再看**，
不然量到的是玩家自己的字。

### 4. 事件点位置要避开冒烟测试的路线

泉水原来放 `(1,1)`，正好撞上"空地是空白"那条断言用的格子；
石龛原来放 `(6,1)`，在"往右走三步"的路径上会被踩到。
最后定在 泉水 `(1,2)` / 地砖 `(2,2)` / 石龛 `(5,2)` / 铜钱 `(6,4)`，
全部避开现有断言用到的格子与路线。

**加内容时要回头看一眼测试用了哪些格子** —— 这是第 14 轮"NPC 挡路带偏路线"的同一个坑。

### 5. `reach` 不能拿 `fire()` 的 `ok` 当条件

泉水只有 `onUse`，踩上去 `fire(ev, 'step')` 返回 `ok: false`（没有 `onCollide` 可跑）。
一开始写成 `if (hit.ok) G.quests.reach(...)`，于是"走到泉水边"这个任务永远做不完。
